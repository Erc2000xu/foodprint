# 食迹 Foodprint｜安全、隐私与合规基线

> 状态：长期约束；V2 发布前必须逐项复核
> 说明：本文件是工程与运营检查清单，不构成法律意见。

## 1. 适用原则

- 最小必要：只收集提供小组美食记录所需的信息，不把地点搜索、实时位置或到访记录用于广告画像。
- 权限优先：认证、RLS、Storage、RPC 和服务端接口共同校验，前端隐藏不是权限控制。
- 默认私密：成员、照片、到访感受、地址相关信息只在授权小组内可见；不生成可猜测的公开资源 URL。
- 安全运营：密钥不进 Git，日志不泄露个人数据，异常有告警、降级、恢复和复盘。

## 2. 数据与用途台账

| 数据 | 用途 | 可见范围 | 控制 |
| --- | --- | --- |
| 账户标识、昵称、邮箱 | 登录、成员关系、必要通知 | 本人；普通界面仅显示昵称；其他成员邮箱及账户治理仅对 Owner 可见 | Supabase Auth、Owner 专用 RPC、RLS、最小字段 |
| 小组与角色 | 授权和治理 | 对应小组 | RLS、角色变更审计 |
| 地点、到访日期、推荐强度、标签、文字 | 发现、地点详情和个人回顾 | 授权小组 | 小组成员检查、删除/导出路径 |
| 照片 | 真实记录 | 授权小组 | 私有 Storage、签名 URL、类型/大小限制 |
| 搜索词/临时定位 | 即时地点检索或附近功能 | 默认不持久化 | 服务端代理、日志脱敏、明确授权 |
| 运行日志 | 安全、稳定与排障 | 维护者最小范围 | 聚合指标、访问控制与保留期 |

## 3. 工程最低要求

1. 所有业务表开启并测试 RLS；读、写、删、Storage 对象和 RPC 均按匿名、Member、Admin、Owner 角色测试。
2. 服务密钥、高德 Web Service Key、地图安全密钥、数据库连接串只在 Secret 管理器；泄漏疑似即轮换。
3. 所有外部接口实施精确 Origin 校验、认证/授权、请求体校验、速率限制和错误脱敏；禁止宽泛 CORS。
4. 上传限制 MIME、体积、数量和对象路径；阻止可执行内容；检查签名 URL 生命周期和撤销行为。
5. 查询使用参数化/RPC，前端不信任；对批量导出、邀请、上传和搜索设置合理频率控制。
6. 依赖升级、构建、类型/Lint、权限测试、备份恢复和灾备演练均纳入发布门槛。
7. Owner、Admin、Member 的资料字段和账户治理权限必须分别测试：只有 Owner 能读取其他成员邮箱或进行账户管理；其余界面不得返回邮箱。

## 4. 内容与用户权利

即使 V1.3 不做评论互动，用户生成的文字和照片仍需要：删除入口、举报/联系渠道、管理员最小化处置流程、处理记录、数据导出与账户注销路径。产品上线前应提供清晰的隐私政策与必要告知，说明收集项、用途、保存、共享、存储区域、用户权利和联系方法。

## 5. 中国大陆发布复核

V2 切换大陆域名与腾讯云前，需由实际运营主体结合服务性质、用户规模、商业化方式、数据存储位置和跨境访问方式，向合格法律/合规顾问确认备案、许可、个人信息处理、数据安全、网络安全、跨境数据及第三方服务义务。工程团队必须提供可核对的数据流和配置台账，不能以“已备案”替代所有合规判断。

参考官方资料：个人信息保护法、数据安全法、网络安全法与工业和信息化部互联网信息服务备案指引。法律文本与监管要求会更新，发布时应重新核验。

## 6. 发布检查与事件响应

### 发布前

- 数据字段、用途、权限、保留期、删除/导出与第三方流向已更新。
- Secret 扫描、RLS/Storage 角色测试、接口滥用测试、依赖检查和备份恢复测试通过。
- 隐私政策、服务条款、联系方式、投诉/删除路径与页面实际行为一致。

### 发生异常时

1. 先止损：禁用可疑 Key、撤销签名链接、收紧接口或下线受影响功能。
2. 保存最小必要证据，限制访问人员；不要在群聊或工单粘贴密钥和完整个人数据。
3. 评估涉及的数据、用户、时间、根因和已采取措施；按适用法律、合同和平台规则寻求专业意见并履行通知义务。
4. 完成修复、权限复测、密钥轮换、复盘和文档更新。
