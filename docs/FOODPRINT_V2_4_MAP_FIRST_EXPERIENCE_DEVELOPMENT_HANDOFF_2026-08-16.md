## 0. 本交接的用途

V2.3 已完成动态地图、列表、Pin、地点卡片和当前视野抽屉的基础闭环，但 2026-08-16 的正式生产使用反馈暴露出三类问题：

1. **生产正确性回归：** 旧照片在所有地点卡片中消失，正式三档 Pin 没有真正显示；
2. **界面体验不足：** 图形内文字仍有垂直偏移，地图主界面被搜索和筛选占去过多高度；
3. **合规回归：** 已上线的 ICP 备案信息从正式页面消失。

此外，当前“点 Pin → 底部卡片 / 当前范围列表”的交互虽然能运行，但还没有形成适合作为最高频主界面的产品体验。

本文完成四件事：

- 把所有反馈转成可追踪的 V2.4 工作项、优先级和验收标准；
- 记录已从代码审计中确认的高概率根因，避免实现阶段只做表面 CSS 修补；
- 将已确认的地图主界面方案写成可直接开发、测试和验收的 UI / 交互合同；
- 明确正式资产、底层产品规则、非范围与发布门禁，防止实现阶段扩大范围或误用演示占位物。

V2.4 不应被定义成一次普通“视觉优化”。它必须按以下顺序执行：

## 3. V24-06｜备案信息恢复与永久门禁

### 3.1 当前高概率根因

现有 `SiteComplianceFooter` 不是被删除，而是依赖：

```text
NEXT_PUBLIC_ICP_RECORD
```

变量为空时组件直接不渲染。现有 GitHub Actions 会把变量传入 Docker 构建，但发布凭据检查没有把它列为必填，因此变量缺失时仍能成功生成并发布一个“没有备案页尾”的生产镜像。

生产页面的可访问结构中也没有备案文本，更符合“构建时未渲染”，而不是单纯被底部导航遮挡。

### 3.2 V2.4 决定

ICP备案号已经确认、公开且不是秘密。V2.4 不再把它作为可以为空的可选视觉配置。

推荐实现：

1. 将已确认备案号放入版本控制下的合规常量；
2. 根布局无条件渲染 `SiteComplianceFooter`；
3. 正式首页使用底部中央的备案链接；地图模式为它预留真实布局空间，不允许被固定底部导航或抽屉覆盖；
4. 若继续保留环境变量，只能作为经过格式校验的显式覆盖，生产缺失或不匹配必须让构建失败；
5. 发布后同时检查裸域和 `www` 规范跳转后的首页；
6. 备案信息缺失、文字不符或链接不是 `https://beian.miit.gov.cn/` 时，整次发布判失败。

本项目已确认的公开备案号以既有备案规格为准：

```text
京ICP备2026047829号-1
```

### 3.3 防回归门禁

- 组件测试：准确备案号与工信部链接必须存在；不再保留“生产空值也合法”的测试。
- 根布局测试：所有路由共享同一合规组件；业务页面不能自行决定是否显示。
- 构建检查：生产构建产物中必须包含备案号。
- 生产冒烟：发布后请求正式首页，验证备案号与链接。
- 视觉验收：320 / 390 / 430px、桌面、PWA standalone 下不被底部导航或安全区遮挡。
- 变更保护：删除或移动合规组件必须同时修改专门测试和本稿，普通页面重构不能静默带走它。

官方依据与运维说明：

- [工信部《非经营性互联网信息服务备案管理办法》第十三条](https://www.miit.gov.cn/zcfg/xxtxl/art/2024/art_7e48434c08c24131b4b7eecfca5b2b6c.html)
- [腾讯云备案号悬挂说明](https://cloud.tencent.com/document/product/243/61412)
- [项目既有 ICP 展示规格](./specs/2026-08-icp-filing-display.md)

> 本节是工程防回归方案，不替代针对实际运营主体的法律意见。

## 4. V24-01｜历史照片恢复

### 4.1 已确认的代码风险

V2.3 的发现索引只把满足以下条件的照片选为封面：

```text
thumbnail_object_key is not null
```

而 V2.2 的旧图 thumbnail 回填只完成了脚本和流程，发布记录明确没有宣称生产全量回填完成。因此，只要历史照片仍有 canonical 原图、但没有 thumbnail 元数据，V2.3 会把它当成“没有封面”，前端最终显示“暂无照片”。

此外，当前 `/api/photos/sign` 也只签 thumbnail key。即使卡片拿到 photo ID，只要 thumbnail 缺失，签名接口仍会返回空列表。

### 4.2 V2.4 修复原则

1. **不删除、不覆盖历史原图。** 所有修复都是向前兼容和可回退的。
2. **“暂无照片”只表示真的没有可见照片。** 缩略图尚未生成必须是可恢复状态，而不是内容缺失状态。
3. **先恢复可见性，再完成性能治理。** 历史图片可暂时按需使用 canonical 原图兜底，随后受控生成 thumbnail。
4. **浏览器只提交 photo ID。** object key、签名 URL和服务端错误不能进入日志或普通组件属性。
5. **RLS、隐藏、软删除和当前小组权限保持不变。** 不为修图片放宽 Storage 或数据库读取范围。

### 4.3 建议实现

#### A. 只读生产审计

先统计，不写数据：

- 当前小组可见照片总数；
- `thumbnail_object_key is null` 的可见历史照片数；
- 有可见 canonical 原图但发现索引 `cover_photo_id is null` 的地点数；
- 签名接口 200 / 空结果 / 403 / 5xx 的分类；
- 新上传照片与旧上传照片分别抽样。

审计只输出计数和脱敏错误分类，不输出用户、地址、object key 或签名 URL。

#### B. 向前 migration 与读模型

- 新增 V2.4 migration，不修改已发布的 V2.2 / V2.3 migration；
- 封面选择第一张当前可见照片，不再要求它已经有 thumbnail；
- 返回 photo ID、可用尺寸与“是否有 thumbnail”的最小状态；不返回 object key；
- 保持完整索引分页、权限和地图 / 列表数据一致性。

#### C. 安全签名兜底

`/api/photos/sign` 根据当前成员权限与 photo ID 在服务端决定资源：

```text
有 thumbnail → 签 thumbnail
没有 thumbnail 但有可见 canonical → 临时签 canonical
照片隐藏 / 删除 / 跨组 / 无权限 → 不返回
```

canonical 兜底只用于恢复历史内容，不改变“新上传必须生成 thumbnail”的主路径。

#### D. 受控回填

- dry-run → 1–2 张测试 → 小批量 → 全量；
- 每批最多 20，并发最多 2；
- 失败率超过阈值立即停止；
- 回填后核对数据库元数据、Storage 对象和卡片实际显示；
- 孤儿审计只报告，不自动删除。

### 4.4 验收

- 历史有图地点在列表卡、地图选中卡、当前范围列表和详情页显示真实照片；
- 真正无图地点才显示“暂无照片”；
- thumbnail 缺失时 canonical 兜底可见，回填后自动走 thumbnail；
- 图片 403 时最多重签一次，失败文案不把“加载失败”误写成“暂无照片”；
- 跨组、已删除、已隐藏照片不可通过 photo ID 越权签名；
- 首屏图片体积和解码不能退回长期加载全部原图。

## 5. V24-03｜Foodprint 三档 Pin 真正接入

### 5.1 结论：不是高德技术限制

高德 JS API 2.0 明确支持 `renderMarker` 与 `renderClusterMarker` 自定义内容，因此三档 Foodprint Pin 在技术上可以实现。当前生产出现默认蓝色 Pin 是接入错误，不是供应商不允许。

高概率根因已经可以从官方合同和当前代码对应起来：

- 高德官方 `renderMarker` 回调只保证提供当前 `marker`；
- 当前代码尝试从 `context.data` 或尚未设置的 `marker.extData` 读取 `placeIndex`；
- 读取失败后直接 `return`，没有执行 `marker.setContent(...)`；
- 高德于是保留默认蓝色 Marker，正好与生产截图一致。

参考：[高德 MarkerCluster 官方参考](https://lbs.amap.com/api/maps-javascript-api/reference/amap-marker/markercluster)

### 5.2 V2.4 修复原则

1. 业务 ID 映射必须经过真实高德运行时 spike，不再假设未文档化字段会透传。
2. 无法解析业务地点时不能静默显示高德默认 Pin；应上报错误并安全降级。
3. 三档等级、选中态、聚合态和用户位置使用现有正式资产，不重新做一套视觉。
4. 点击 Pin 必须解析到唯一的 `group_place_id`；不得用地点名作键。
5. 相同坐标、筛选更新、选中切换和聚合解散必须进入集成测试。

### 5.3 实施路径

先做一个真实 AMap MarkerCluster 最小 spike，记录以下实际合同：

- `renderMarker` 的 marker position、extData 和 click event 能得到什么；
- 自定义 dataOption 字段是否保留；
- `setData` 后 Marker 是否复用；
- 相同坐标和最大 zoom 的行为；
- 聚合 click 是否能得到成员集合。

根据 spike 选择：

- 直接自定义 `AMap.Marker` 并显式写入 `extData`；或
- 使用经验证的局部索引 / 坐标桶映射；或
- 为当前私密小数据集使用可控的自有聚合层。

不得继续依赖当前已经在生产失败的 `context.data → placeIndex` 假设。

### 5.4 验收

- 真实高德地图上没有默认蓝色地点 Pin；
- 1 / 2 / 3 级 Pin 分别对应“值得去 / 想再去 / 会专门去”；
- 选中 Pin 100ms 内出现已批准选中态，锚点不跳；
- 聚合数字、点击放大和到顶展开成员正确；
- 每个 Pin 点击后打开正确地点，不串店；
- 相同坐标地点不会丢失或误跳；
- 资产 404 或映射失败时进入可观察错误，不带病上线。

## 6. V24-02｜图形内文字统一居中

### 6.1 当前问题

V1.4.1 已经给普通按钮补过统一居中规则，但 V2.3 新增的地图浮层并没有全部复用。例如：

```text
朋友推荐了 4 个地点
```

当前使用 `strong + min-height + padding`，没有 `display:flex/inline-flex + align-items:center`，所以文字基线视觉上靠上。

这说明问题不能继续靠逐个页面“调 1–2px”，而要建立组件合同。

### 6.2 几何居中合同

所有承载短文字的封闭图形统一遵守：

- `box-sizing: border-box`；
- `inline-flex` 或 `grid`；
- 主轴与交叉轴同时居中；
- 高度由固定 / 最小高度控制，避免上下 padding 和字体行高共同决定位置；
- `line-height` 使用统一可读值；
- icon + label 作为一个整体居中；
- 多行按钮允许换行时，以内容组整体居中，不裁切文字；
- 文本卡片、搜索结果正文等信息内容仍按阅读方向左对齐，不强行居中。

覆盖范围：

- 搜索按钮、三项意图筛选；
- 列表 / 地图分段切换；
- 地图顶部数量浮层与定位按钮；
- 当前范围摘要、抽屉标题与操作；
- chip、badge、空状态操作、管理菜单；
- 底部导航图标与文字；
- V2.4 新增的所有地图卡片控件。

### 6.3 验收

- 320 / 375 / 390 / 430px；
- iOS Safari、Android Chrome、桌面 Chrome、PWA standalone；
- 中文、数字、中英混排、icon + label、1 行与 2 行；
- 100% 与系统大字体；
- 截图差异检查不能只验证 DOM 中存在 `align-items`，必须看真实像素位置。

## 7. V24-04 / V24-05｜已批准地图主界面 UI 与交互实施规格

本节是 V2.4 地图模式的规范性合同。除非本文明确标注为“建议”或“可选”，开发、测试和验收都必须遵守；若实现与演示稿不一致，以本节、产品底层规则和视觉资产台账为准。

### 7.1 设计目标与不变边界

地图模式的第一任务是让用户在朋友已经真实推荐的地点中，通过位置、筛选和快速比较决定“今天去哪儿吃”。它不是公开餐厅目录，也不是高德周边搜索入口。

必须保持：

1. 地图、列表、搜索结果和当前范围列表来自同一个已授权推荐集合；
2. 高德搜索建议只帮助确定地区或坐标，不得把公开 POI 注入 Foodprint 发现结果；
3. “值得去 / 想再去 / 会专门去”三级语义、数据值与正式 Pin 映射不变；
4. 底部五项导航的名称、顺序、路由与现有正式图片资产不变；
5. 真实照片、成员可见性、RLS、软删除、隐藏和小组权限不变；
6. ICP 备案组件继续由根布局统一拥有，任何地图重构不得条件隐藏或覆盖它；
7. V2.4 不借地图优化之名重做品牌 Logo、正式 Pin、底部导航图标、字体系统或全站视觉系统。

### 7.2 演示稿与正式资产边界

2026-08-16 的 UI 演示稿只批准以下内容：

- 地图优先的空间比例；
- 顶部安全留白和半透明叠层关系；
- 紧凑搜索与筛选 chip 的位置、材质和状态；
- 地图、顶部控件与底部面板形成的前后层次；
- 当前范围摘要、单店预览、当前范围列表三种语义状态；
- Pin 点击、筛选、上拉、列表选择和详情往返的交互流程。

演示稿中的下列元素是占位物，明确不具备资产批准效力：

| 元素 | 正式实现唯一真相源 | 禁止事项 |
| --- | --- | --- |
| 品牌 Logo / 吉祥物 | public/mascot/icon-192.png，以及现有 App Header 组件 | 不使用演示稿中的 emoji、临时犬形或重新生成的 Logo |
| 地图地点 Pin | IC-08 B「餐盘定位圆章」及 map-pin-assets / map-pin-elements 统一入口 | 不使用演示稿 CSS 圆点、餐具符号、默认蓝 Pin 或另画的新 Pin |
| 底部导航 | public/nav-icons/ 下现有五项资产、现有标签和顺序 | 不抄演示稿的临时图标，不改变“记一顿”的中央强调关系 |
| 地点照片 | DiscoveryCardPhoto 的真实私有图片链路 | 不使用演示照片、假菜图或公开 POI 图片 |
| 地图底图 | 高德 JS API 正式底图与已验收官方样式 | 不把演示稿的示意道路、颜色或透视图当成底图资产 |
| 字体与功能图标 | 当前字体令牌与视觉资产台账中的受控 SVG / 组件 | 不因演示稿引入新字体、emoji 功能图标或未登记位图 |

任何临时对话图、HTML 演示或截图中的视觉元素，只有先进入 VISUAL_ASSET_REGISTRY、完成确认并保存为项目正式资产后，才允许替换上述真相源。

### 7.3 页面结构与层级

地图模式继续位于现有居中的手机应用壳中；桌面端保留外侧背景，不在 V2.4 把发现页改造成宽屏后台。手机壳宽度、底部导航和页面路由均沿用现有 AppShell。

从后到前的层级固定为：

| 层级 | 内容 | 实施要求 |
| --- | --- | --- |
| L0 | 高德地图画布 | 填满地图舞台，不再放入带 22px 圆角、边框和外边距的独立卡片 |
| L1 | 正式 Pin、聚合、用户位置 | 只使用 IC-08 正式资产；锚点和命中区遵循 Pin 规范 |
| L2 | 地图原生归属标识与地图控件 | 高德 Logo / copyright 保持原生；定位、数量等业务控件避开安全区 |
| L3 | 顶部品牌、搜索、筛选叠层 | 覆盖在地图上方，不把地图整体向下推 |
| L4 | 当前范围 / 单店底部面板 | 非模态；遮挡高度必须同步为地图 bottom padding |
| L5 | 全局底部导航 | 使用现有固定导航；不得被地图或面板覆盖 |
| 文档流 | 全局 ICP 备案页尾 | 由根布局输出，在页面底部中央可见且可访问，不属于地图悬浮层 |

地图舞台必须是 Header 与底部导航之间最大的连续视觉区域。列表模式仍使用现有文档流和完整卡片布局；两种模式不强求同一首屏骨架。

### 7.4 顶部安全留白与半透明品牌层

顶部不再贴住物理屏幕边缘，也不再使用一整块有硬分隔线的米白色抬头。

实施尺寸：

- 顶部起始间距使用 max(calc(env(safe-area-inset-top) + 10px), 20px)；
- 375px 及以上屏宽的左右安全边距为 16px；320px 屏宽允许收紧到 12px，但不得贴边；
- 品牌行建议高度 36px，沿用现有 34px 正式 Logo、产品名和当前共同地图状态；
- 品牌行与搜索框间距 8–10px，搜索框与筛选行间距 8px；
- 筛选行下方保留 12–16px 的渐隐缓冲，再进入纯地图区域，使顶部四周都有呼吸空间而不是形成硬框；
- 整个顶部叠层不得设置会截断阴影、下拉菜单或焦点环的 overflow hidden。

材质合同：

- 背景以现有 --color-surface / --color-bg 为基色，使用约 72%–88% 的透明度渐变；
- 可使用 16–20px backdrop blur 和轻度饱和度增强；不支持模糊时退化为约 94% 的不透明暖色表面；
- 地图纹理可以在品牌行和控件间的空隙隐约透出，但文字下方必须有足够实底保证对比度；
- 不使用从左到右贯穿整屏的硬边框；层级由渐隐、轻阴影和控件自身边界表达；
- 阴影采用低对比、软扩散；禁止厚黑描边、高饱和大色块或同时叠加多层重阴影；
- V2.4 继续使用当前浅色产品外观；演示稿中的深色模式不构成本版需求。

建议新增三个地图局部令牌并由控件统一复用：--map-overlay-surface 以 --color-surface 约 82% 混合透明；--shadow-map-control 基准为 0 8px 24px rgb(24 59 58 / 10%)；--shadow-map-sheet 基准为 0 -10px 30px rgb(24 59 58 / 12%)。不支持 color-mix / backdrop-filter 时使用前述近不透明退化，不允许各组件自行选一组新颜色和阴影。

正式 Header 内容必须来自现有 AppShell：真实品牌 Logo、“食迹”以及真实 groupName / 当前共同地图状态。地图模式通过 AppShell 的 map variant 把同一个 Header 变成叠层，不得额外复制第二个品牌头；列表模式继续使用现有实底 Header。演示稿文案不得硬编码进组件。

### 7.5 地图模式搜索框

地图模式保留一行紧凑搜索，不显示“今天想去哪儿吃？”大标题、长说明和三块大意图按钮。

搜索框合同：

- 高度 48px，圆角 18px，左右内容内边距 14–16px；
- 搜索图标、输入文字、清除按钮和提交按钮在同一几何中心线上；
- 输入占位继续覆盖餐厅、区域、商圈、地铁、菜系和推荐菜；
- 清除和提交的实际命中区均不少于 44 × 44px；
- 搜索建议浮层锚定在搜索框下方，左右与搜索框对齐，最大高度不超过 46dvh；
- 键盘打开时优先保持输入框和当前建议可见，不强行维持底部面板展开；
- 提交搜索后只过滤授权 BaseSet，并同步更新 Pin、总数、ViewportSet 和列表模式；
- 搜索为零结果时保留地图、中心和缩放级别，显示轻量“没有符合条件的地点，试试清除筛选”，不得加入高德公开结果填充页面；
- 切换到列表模式再返回时，搜索词、已提交条件和地图上下文不得丢失。

### 7.6 快捷筛选 chip 与下拉框

地图模式第一批必须提供三类快捷筛选：

| chip | 数据来源与语义 | 选择方式 |
| --- | --- | --- |
| 地区 | 复用现有城市 / 区县 / 商圈 / 地铁地点筛选；同一时刻只保留一个主地区条件 | 单选；选择后立即提交并关闭 |
| 餐馆类型 | 复用现有餐饮分类 / 菜系状态，不新建第二套分类字典 | 可多选；点击“完成”后统一提交 |
| 推荐等级 | 复用 1 / 2 / 3 级推荐值与正式中文标签 | 可多选；点击“完成”后统一提交 |

状态模型必须落实为同一 SearchState：地区继续使用单一 locationFilter；餐馆类型由现有 categoryOptions 与 cuisineOptions 分组展示，并分别写入 categoryIds / cuisineIds；推荐等级新增 recommendationLevels: Array<1 | 2 | 3>，按地点汇总后的 bowlStrength 过滤。URL 使用可规范化的 category、cuisine、level 参数，逗号分隔、去重、校验非法值并限制数量；列表与地图不得各自维护一份隐藏状态。

chip 视觉与状态：

- 高度 36px，左右内边距 12–14px，圆角为胶囊形，间距 8px；
- 筛选行允许横向滚动，不换成两行压缩地图；隐藏滚动条但保留键盘和触控滚动；
- 默认态使用半透明暖白表面、细边界和深青文字；
- 生效态使用浅鼠尾草底、深青边界 / 文字和清晰选中标记，不用高饱和实心块；
- 单项生效显示具体值；多项生效显示“餐馆类型 · N”或“推荐等级 · N”；
- 提供独立“清除”入口；仅在确有筛选时出现，不能占用默认首屏宽度；
- chip 及其展开按钮必须提供 aria-expanded、aria-controls 和可读名称。

下拉框合同：

- 一次只允许打开一个筛选框；
- 锚定在对应 chip 下方；优先左对齐，超出视口时贴近左右 14px 安全线；
- 最小宽度 184px，最大宽度 calc(100vw - 28px)，圆角 18px；
- 使用近不透明表面，不能让地图道路文字穿透到选项文字中；
- 选项行视觉高度不低于 40px、命中区不低于 44px；长列表最大高度 46dvh，内部滚动；
- 地区单选即时提交；餐馆类型和推荐等级在浮层内先形成草稿，只有“完成”才写入 URL / 正式筛选状态，“清除”只清当前分类；
- 点击外部、Escape、浏览器返回或再次点击同一 chip 关闭浮层；未点“完成”的多选草稿应回退；
- 打开时焦点进入浮层首个可操作项，关闭后焦点返回原 chip；
- 下拉浮层负责阻止自身事件穿透地图，但不得改变地图中心或重新创建地图实例。

地图与列表复用同一份规范化 URL / search state。列表模式可以继续提供“按地点找 / 按菜系找 / 找灵感”等完整入口；地图快捷 chip 只是同一状态的紧凑编辑器，不是新的筛选系统。

### 7.7 地图尺寸、底图与视觉纵深

地图不再使用旧版“米白页面里嵌一张圆角地图卡”的结构。地图画布应从顶部叠层下方延伸到面板 / 底部导航上方，首屏目标为可用内容区约 65%–70%，并在较高设备上继续增长。

地图视觉合同：

- 使用高德 JS API 2D、北向上的稳定地图交互；V2.4 不强制旋转、倾斜或伪 3D；
- “透视感 / 纵深感”来自全幅地图、顶部半透明层、控件软阴影、Pin 层级和底部面板遮挡关系，而不是把道路与文字做透视变形；
- 正式底图优先沿用 V2.3 当前候选“远山黛”，并在真实高德地图、多种屏宽和三种面板状态下完成可读性验收后固定；若验收失败，只能在高德官方样式中调整并留截图证据；
- 不自行重绘道路、行政区、水域或高德地名；不把演示稿颜色当成新的地图设计令牌；
- 不为了突出 Foodprint 控件而隐藏高德必要地名、Logo 或版权信息；
- 地图页主要操作无需整页纵向滚动；长内容只在当前范围列表或地点详情中滚动；
- 面板状态变化只调整 map padding / 可见视口，不销毁或重新初始化 AMap 实例。

### 7.8 地图控件与高德归属标识安全区

业务控件采用小体积、弱边界、强命中区的原则：

- “列表”入口和符合条件地点总数置于顶部筛选层或其下方的清晰位置；
- 定位按钮优先置于地图右侧、底部面板上方，并随面板高度上移；
- 任何圆形图标按钮视觉直径可以为 36–40px，但命中区必须至少 44 × 44px；
- 数量、定位和列表入口不能压住 Pin、搜索建议、筛选下拉或底部面板；
- 所有图形内短文字遵守第 6 节几何居中合同。

高德 Logo / copyright 是不可占用的 Provider Attribution Safe Zone：

- 使用高德 JS API 自行注入的正式标识，不自行临摹、替换、重复绘制或翻译；
- 不通过 .amap-logo、.amap-copyright 等未公开 DOM / CSS 选择器隐藏、缩小、降透明度或强制移位；
- 左下角至少预留约 12px 外侧空间，标识上方和右侧至少预留 8–12px，不放业务按钮、可点击内容或重要文字；
- 摘要、单店预览、当前范围列表三种面板状态下，标识都必须处于仍可见的地图区域；
- 若高德 JS API 没有公开偏移能力，通过地图舞台可见高度、bottom padding 和 resize 协调，而不是操作高德内部 DOM；
- 320 / 390 / 430px、浏览器、PWA standalone 及各面板状态必须留真实高德截图证据。

官方依据：

- [高德 JS API 2.0：左下角 Logo 与 logoLanguage](https://lbs.amap.com/api/javascript-api-v2/guide/map/englishmap)
- [高德地图平台服务条款：不得移除或模糊品牌及版权标识](https://lbs.amap.com/api/policies/terms)

当前公开文档只明确 Logo 语言设置，未给出位置偏移参数；“通过容器和地图 padding 协调”是基于现有官方文档的工程边界，编码时仍需在正式运行时复核。

### 7.9 正式 Pin、聚合与选择反馈

V2.4 只修复 IC-08 正式资产接入，不重新设计点位：

- 默认 Pin 40 × 45px，选中 Pin 48 × 54px；实际命中区至少 44 × 44px；
- 使用底部中心锚点；单点、聚合和用户位置遵循正式 Pin README；
- 三档推荐等级必须映射到对应正式 SVG；
- 选中态在点击后 100ms 内同时表现尺寸和橙红轮廓变化，不能只依赖颜色；
- 聚合显示 1–99 / 100+，使用正式 default / active 资产；
- 用户位置继续使用独立蓝色资产，不能与业务地点 Pin 混淆；
- 食迹地点不得回退成高德默认蓝色大头针；若业务映射失败，应记录脱敏错误并降级到列表，不能静默显示错误语义；
- 页面不得散写 Pin 文件路径，也不得用演示稿图形临时补位。

### 7.10 底部面板只保留三种语义状态

V2.4 用三种可理解的任务状态替代通用 peek / card / half / expanded 四档。不得在本版增加第四个接近全屏的 detent。

面板贴合地图舞台左右和底部，不再嵌成地图卡片里的第二张小卡；只有上方两个圆角，基准半径 24px。表面使用 96%–100% 的现有暖白 surface，配统一 --shadow-map-sheet，保证正文不受底图干扰。可见 grabber 基准 36 × 4px，但其透明命中区至少 44 × 32px，并与标题区共同形成明确的拖动入口。

#### S1｜当前范围摘要

- 默认高度基准 76px，允许在 72–78px 内因大字体调整；
- 显示“当前范围 · N 家”、已生效筛选的简短摘要和“上拉查看列表”；其中 N 始终是 ViewportSet 数量，不是全部 FilteredSet 数量；
- 整个摘要 / 标题区都是明确的 44px 以上操作区域；
- 点击摘要直接进入 S3；从摘要区上拉也进入 S3；
- 地图空白处无选择时默认回到该状态。

#### S2｜单店预览

- 高度基准 190px，允许在 184–210px 内适配内容与大字体；
- 只显示当前选中的一张地点卡，不在卡片下方同时塞当前范围列表；
- 字段顺序固定为：真实封面图、地点名、推荐等级、菜系 / 区域 / 朋友人数、最多一行推荐菜或短评、明确“查看详情”；
- 无真实图片时使用项目正式无照片状态，不使用演示图片；
- 提供次级入口“看看附近另外 N 家”，进入 S3；
- 点击卡片主体或“查看详情”进入地点详情；拖动只能从固定 grabber / 标题区开始，避免与卡片点击混淆。

#### S3｜当前范围列表

- 默认高度使用 clamp(320px, 46dvh, 420px)，在 320px 矮屏上优先保证地图与高德归属标识仍可见；
- 顶部固定显示“当前范围 · N 家”、grabber、关闭 / 收起能力；
- 每行包含真实小图、地点名、推荐等级、菜系 / 区域；其余长字段留到 S2 或详情；
- 行命中区不低于 56px；长列表在面板内容区内部滚动；
- 点击一行使地图定位并高亮对应 Pin，面板切换为 S2；
- S3 只显示当前地图视野内的 ViewportSet；想浏览完整 FilteredSet 时使用顶部“列表”模式；
- 列表为空时显示当前范围空状态和“缩小地图 / 清除筛选”，不显示高德公开 POI。

三种状态的高度都通过实际测量写入地图 padding，不依赖散落常量猜测。内容因大字体超出允许高度时，优先让内容区滚动或减少次要字段，不裁切核心操作。

状态机用业务语义命名为 summary / place_preview / viewport_list，不再把像素高度作为业务状态。summary 必须没有 SelectedPlace；place_preview 必须有有效 SelectedPlace；viewport_list 可以保留当前高亮地点，但只渲染 ViewportSet。SELECT_PLACE、CLEAR_SELECTION、OPEN_VIEWPORT_LIST、COLLAPSE_SHEET、FILTER_CHANGED 和 RESTORE_RETURN_STATE 必须经过同一 reducer，避免组件各自改高度与选择状态。

### 7.11 手势隔离与点击体验

抽屉与地图必须通过“起点归属”消除抢手势：

1. 从地图画布开始的拖动永远平移 / 缩放地图，绝不触发面板；
2. 只有 grabber、摘要区和面板固定标题区可以开始面板垂直拖动；
3. 折叠态保留 72–78px 真实触控面，不能把上拉入口缩成一根 5px 细线；
4. 列表内容区只滚动列表；到达列表顶部也不自动把滚动接力给面板，收起必须回到固定标题区或点击关闭；
5. 面板范围内的 pointer / touch 事件必须被面板接收，不能穿透给高德地图；
6. 指针移动 8–12px 后判定方向；只有以垂直为主的标题区手势锁定为面板拖动；
7. 拖动过程连续跟手，位置更新通过 requestAnimationFrame 合并；松手根据距离与速度吸附最近合法状态；
8. 轻点摘要是与上拉等价的无手势替代，轻点 Pin 是与拖图明确区分的选择动作；
9. Escape / 浏览器返回优先按“关闭筛选浮层 → S3 收回到 S1（若保留有效选中地点则回 S2）→ 清除 S2 选择 → 离开页面”的层级处理；
10. prefers-reduced-motion 下关闭非必要弹性与缩放，仍保留明确即时状态反馈。

必须在真机测试：地图底部横向拖动、斜向拖动、双指缩放、从摘要上拉、从标题下拉、列表内快速滚动、连续点不同 Pin，以及面板动画中再次操作。

### 7.12 搜索、筛选、地图与面板的状态合同

统一使用以下集合定义，避免列表与地图各算一套：

- BaseSet：当前小组有权查看的真实推荐地点；
- FilteredSet：BaseSet 经搜索和筛选后的结果；
- ViewportSet：FilteredSet 中落在当前地图可视范围内的结果；
- SelectedPlace：当前选中的一个 Foodprint 地点，可为空。

状态变化规则：

| 用户动作 | 地图 / Pin | 面板 | URL / 恢复 |
| --- | --- | --- | --- |
| 提交搜索或筛选 | 增量更新 FilteredSet 和 cluster data，不重建地图 | 计数同步；若选中地点被排除则清空选择回 S1 | 写入规范化 search state |
| 拖动 / 缩放地图 | moveend / zoomend 后计算 ViewportSet | S1 数量更新；S3 在移动结束后稳定更新，不在手指拖动时跳动 | 记录 center / zoom |
| 点击单个 Pin | 设为 SelectedPlace、显示正式选中态，并按当前面板高度安全平移 | 进入 S2 | 记录 selectedPlaceId |
| 点击地图空白 | 清除 SelectedPlace | S2 回 S1；S3 不因空白点击意外关闭 | 保留筛选、center / zoom |
| 点击聚合 | 优先放大到可分离层级；达到上限或重叠无法分离时显示对应地点列表 | 进入 S3 | 保留 cluster 上下文 |
| 点击 S3 行 | 高亮并安全定位到该 Pin | S3 → S2 | 记录 selectedPlaceId |
| 点击“看看附近” | 保留当前 Pin 选中态 | S2 → S3 | 不改变筛选 |
| 切到列表 | 不销毁搜索 / 筛选状态 | 地图面板状态暂存 | URL 保留 view、筛选和恢复令牌 |
| 进入详情再返回 | 恢复 center、zoom、FilteredSet、SelectedPlace | 恢复离开前的 S1 / S2 / S3 | returnTo 不得丢状态 |

同一次筛选更新必须让 Pin、地图数量、当前范围列表和完整列表在同一提交周期内一致。零结果、失败降级或权限变化时，不能保留已无权访问的 SelectedPlace。
