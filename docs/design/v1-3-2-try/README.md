> 生成方式：内置 ImageGen，类型为高保真移动端 UI 概念稿。

> 产品结论：更偏向 B“出发地图”；三套稿均保留为 V3 底稿，不在 V1.3.2 实施整体页面视觉改版。

## A｜城市便笺

- 最接近直接落地的结构。
- 搜索、当前位置、候选信息和三类操作层级清楚。
- 便笺只应保留轻微纸张感；正式卡片把期待限制为两行，避免被长文撑高。

## B｜出发地图

文件：`direction-b-route-map.png`

- 更强调从“想去”到“出发”的路线感。
- 适合解释附近搜索和导航。
- 正式开发只保留极浅、低高度的路线辅助线，不保留大块装饰地图，以免降低候选列表信息密度。

## C｜餐桌手记

文件：`direction-c-editorial-journal.png`

- 人文、生活杂志和手记感最强。
- 标题、细分隔线和引用方式可作为品牌语言参考。
- 大号手写引语会显著增加卡片高度，不建议整套直接采用。

## V3 推荐合并方向

以产品负责人偏好的 **B 的轻路线与出发感** 为主，仍采用 **A 的结构与操作层级**控制可用性，只借用 **C 的标题气质、纸张材质和细分隔线**。

正式视觉稿需统一：

- 底部导航继续使用产品现有五项名称，不采用生成图里的文字偏差。
- 所有功能文字改用清晰无衬线字体；手写感只用于主标题或一句期待。
- 导航、定位、编辑等小图标进入 `VISUAL_ASSET_REGISTRY.md` 后再制作。
- 行政区与商圈只展示高德真实数据。

## 生成提示词共同约束

三套方向均使用当前食迹截图作为布局、品牌头部和配色参考；共同要求为 390px 风格的窄屏移动页面、米白/浅鼠尾草绿/深青绿/橙色点缀、完整搜索和候选卡、可见的“导航去这里”和“我去过了”、不使用假餐厅照片、不在卡片放吉祥物、不使用 emoji、不采用通用蓝色 SaaS 风格。三套差异分别为城市便笺、轻路线地图和餐桌手记。
