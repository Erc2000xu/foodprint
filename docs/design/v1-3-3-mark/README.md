# V1.3.3 记一顿表单｜视觉方向稿

> 生成日期：2026-07-30
> 状态：产品讨论用意向稿，不是逐像素开发稿
> 生成方式：内置 ImageGen，使用当前记一顿页面截图作为品牌与内容参考

三套方向都只处理 V1.3.3 的信息层级、解释文案和选择控件，不提前实施 V3 的整体视觉系统。

## A｜清晰单页

文件：`direction-a-clear-single-page.png`

- 保留现有单页直填顺序，学习成本最低。
- 主要依靠留白、字重和浅分隔建立层级，减少大块 fieldset 和重复边框。
- 适合作为小版本的稳妥落地方向。
- 风险是页面仍然较长，推荐强度和“好在哪儿”之间的阶段感不强。

## B｜三段式引导

文件：`direction-b-guided-sections.png`

- 将表单分为“确认这家店 / 说说为什么推荐 / 留下这顿”三段。
- 最能解释每一组字段为什么存在，也便于快速扫描长表单。
- 所有内容仍在同一页，不使用折叠，不会因为返回上一步丢失内容。
- 正式开发不必保留顶部进度线；可只保留三个轻量分组标题，避免让用户误以为必须逐步提交。

## C｜先选择，再补充

文件：`direction-c-choice-first.png`

- 先回答推荐强度和四个体验维度，再补到访日期、分类和可选内容。
- 选择状态最清楚，表单更像一次轻量回忆，而不是资料录入。
- 底部完成状态能直接告诉用户还差什么。
- 风险是信息顺序与传统表单不同，且首屏选择卡占用高度较多。

## 共同约束

- 新地点最上方先确认“亲自去过、也愿意推荐给朋友”。
- 页面只解释一次必填标记，不在每个标题旁反复显示红色“必填”。
- 三级推荐继续使用项目内 `BowlIcon` 和已确认的小碗资产，不使用意向稿中自动生成的小碗替代正式资产。
- “好在哪儿”使用统一的四枚语义图标；意向稿中的图形只表示语义，不是最终资产。
- 新表单不再提供“小吃 / 街头餐饮”大类；其内容并入“餐厅”。
- 上传区域明确首页照片框为宽 : 高 = 3 : 4，并提示横图会居中裁切。
- 正式页面保持准确的五项导航名称：发现、去试试、记一顿、饭后聊、我的。

## 当前建议

产品负责人于 2026-07-30 确认整体偏向 **C“先选择，再补充”**：

1. 先完成推荐强度和“好在哪儿”，再补事实与可选信息。
2. 不引入真正的多步骤提交，仍保持连续单页。
3. 保留字段级错误和底部未完成项提示。
4. 推荐强度在 320px 下使用纵向列表，不照搬意向图中拥挤的横向布局。
5. 意向图中自动生成的小碗与四维图标均不进入开发；小碗必须复用现有 `BowlIcon`，四维图标另行确认正式资产组。
