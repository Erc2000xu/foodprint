## 1. 本轮产品结论

### V1.3.1｜发现页

- 发现卡照片区域采用宽 : 高 = 3 : 4 的竖版比例。
- 三级推荐不再重复显示 emoji；使用三个独立的小碗奖章资产。
- 下回吃不再独占卡片底部一行；未收藏青绿、已收藏红色，并保留爱心与文字说明。
- “好在哪儿”为吃得香、坐得住、聊得开、花得值，必须显示图标、文字和次数。
- 旧场景标签与“好在哪儿”语义分开，不能混作同一种评价。
- 行政区统一为市级 + 区级；商圈只使用高德逆地理编码的真实数据。
- 新旧地点走同一展示组件；历史地点需要受节流地补齐高德商圈。
- 搜索与顶部筛选需要统一状态、点击外部关闭并解决窄屏溢出。

### V1.3.2｜去试试

- 候选卡一级页面增加“导航去这里”。
- 显示高德行政区和真实商圈；无商圈时隐藏。
- 增加用户主动触发的“按当前位置找”，不在页面打开时自动索取定位。
- “我去过了→值得推荐”必须进入完整的记一顿表单，提交成功后才进入发现。
- 从记一顿直接记录相同高德 POI 时，也要把同组候选改为 `promoted` 并从去试试列表移除。
- 候选保留后台状态和审计记录，不物理删除。
- 新表单停止提供“小吃/街头餐饮”大类；历史 `street_food` 兼容显示并前向迁移为“餐厅”。“小吃快餐/面食”继续作为菜系存在。
- V1.3.2 不做整体视觉改版；三套方向稿保留到 V3，产品负责人更偏向 B“出发地图”。

## 6. 工程注意事项

- 不修改历史 migration；所有数据库调整使用新的前向 migration。
- 地点唯一性使用 `source_provider + source_poi_id`，不能用店名字符串去重。
- 高德商圈是可刷新缓存，不建立自有商圈权威库，不猜测缺失值。
- 不得因为新版本改变旧记录的展示组件或丢失旧标签。
- 先查视觉资产台账；未确认的品牌图标不得临时使用 emoji。
- 功能按钮和状态使用成熟的 SVG 图标、文字和无障碍名称。
