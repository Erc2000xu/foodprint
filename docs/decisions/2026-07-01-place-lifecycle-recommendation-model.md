# ADR 2026-07-01｜地点生命周期与推荐模型

> 状态：已确认；V1.2 工程实现中

## 背景

食迹既需要收下“想试”的线索，也要保持发现页只呈现真实推荐。现有单次 mark 模型无法表达候选、验证、重复到访、用户当前观点与历史时间线。

## 决定

1. 地点主数据、候选关系和小组推荐关系分层：同一 POI 在同一小组不因不同用户反复创建多个地点实体。
2. 候选状态为 pending、promoted、dismissed；只有 promoted 对应的小组地点可进入发现。
3. dismissed 仅作最小化后台验证/去重，不构成公开差评内容。
4. 每位用户在每个推荐地点有一份当前观点；该观点参与聚合。每次到访另存为历史记录，保留当时快照。
5. 当前观点的推荐强度为 1 至 3，前端以一至三层小碗显示；聚合为有效用户当前值平均后四舍五入。
6. V1.2 的候选验证只记录“已亲自体验”与“是否值得推荐”。推荐后创建/复用 `group_place`，但不虚构评分、照片或完整观点；这些由 V1.3 的到访与观点模型补齐。

## 原因

这使“先试后推荐”与“多次到访的真实记忆”同时成立，不把高频用户的历史记录误算为多个独立推荐者，也不需要公开负面内容。

## 影响

- 现有单次 place mark 需要通过向前兼容 migration 迁移/适配为首次观点与首次到访记录。
- 聚合统计应按 distinct current opinion 用户数，而不是全部 visit 数。
- 详情时间线保留历史，但地点卡只展示当前汇总。

## 复核条件

若未来开放公开内容、商家主体、跨小组地点共享或负面评价可见性，必须重新审议本模型和隐私边界。
