# ADR 2026-07-29｜V1.3 到访记录的隐私与治理

> 状态：已确认（2026-07-29）
> 适用范围：V1.3 的 current_opinion、visit_record、照片和饭后聊；不构成法律意见。

## 背景

V1.3 会把一次标记扩展为可持续的图文到访记录。这些记录默认只对同一有效小组成员可见，但仍须明确成员退出、管理员处置、内容保存、导出和删除的行为，才能安全设计 RLS、Storage 和前向迁移。

## 已确认决策

| 决策 | 已确认行为 |
| --- | --- |
| 成员退出或注销后的历史记录 | 历史到访、笔记、照片、推荐强度和标签均保留在原小组的地点详情与饭后聊中；作者统一显示为“已离开成员”，不再链接个人资料。该用户保留的当前观点继续参与地点推荐强度与标签人数汇总。 |
| 账户与邮箱可见性 | 只有 Owner 可以管理其他成员账户，并查看其他成员的邮箱地址。Admin 和 Member 均不可查看其他成员邮箱，也不可进行账户管理。所有普通产品界面只显示用户当时设置的昵称。 |
| 管理员处置范围 | Owner/Admin 可基于举报或明显违规，隐藏整条到访或单张照片；不可改写原文、评分或标签，且必须记录操作者、原因和时间。 |
| 用户删除与照片保留 | 作者可删除自己的到访或照片；删除后立即对小组不可见，30 天内完成数据库软删除清理与 Storage 对象物理删除。账户注销不自动删除其既有小组内容，而是按“已离开成员”匿名保留。 |
| 导出与账号注销 | V1.3 提供本人到访文字、标签、菜品和照片元数据的导出；账号注销申请走产品内联系入口，核验后将账户与个人资料注销/去标识化，同时保留既有小组内容。 |
| 匿名提交 | V1.3 的首次与后续到访表单提供“匿名分享给小组”可选项。匿名记录在地点详情、饭后聊、推荐汇总和照片署名处显示为“匿名成员”；昵称和可识别资料不向普通成员暴露。作者本人、Owner 的最小化治理审计和受控导出仍保留真实归属。 |

## 推荐决策的工程后果

1. `current_opinion` 必须与用户账户的活跃成员状态解耦：退出/注销后仍作为保留记录参与汇总，但不得再由已退出账户写入或修改。
2. `visit_record`、`current_opinion` 与照片需要记录匿名展示状态；查询与读模型应将离开成员和主动匿名作者统一映射为不可识别的展示名，不能把邮箱或真实昵称发送到普通客户端。
3. `profiles` 的邮箱字段不得出现在普通成员、Admin、地点详情、饭后聊或导出给其他用户的查询中。账户治理与邮箱读取只通过 Owner 专用 RPC 和 RLS 策略开放。
4. `visit_record` 与 `photos` 必须支持作者删除和 Owner/Admin“隐藏”，不得直接改写历史快照；所有治理操作写入审计事件。
5. Storage 删除采用“先撤销访问、后物理清理”的两阶段流程；实施前需明确 30 天清理任务的运行方式与失败告警。
6. 新增到访数据进入现有导出范围；注销申请的受理路径、身份核验和处理时限需在隐私政策与产品页面中如实说明。

## 确认方式

项目负责人已于 2026-07-29 确认本 ADR。后续的 V1.3 数据模型、RLS、Storage、导出和表单实现均以本决策为准；若需要改变退出内容保留或匿名的真实归属边界，必须新增 ADR 修订。
