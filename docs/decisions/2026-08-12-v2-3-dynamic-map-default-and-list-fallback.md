# ADR｜V2.3 默认动态地图、列表降级与单一地点数据集

> 日期：2026-08-12  
> 状态：已确认  
> 决策人：项目负责人  
> 影响范围：发现页信息架构、地图供应商边界、发现读模型、失败降级、静态地图生命周期

## 背景

Foodprint 的核心产品心智是“共同美食地图”，但此前正式应用运行在 Vercel，国内域名、访问链路和高德 JavaScript API 的安全代理配置尚未稳定，因此发现页长期以列表为主，并使用受保护的静态地图作为过渡。

现在正式域名已经是 foodprint.com.cn，Next.js 应用运行在腾讯云，同源服务端可以代理高德 JS API 安全密钥请求。项目负责人希望优先上线可拖动、可缩放、可点选的动态地图，并采用本地生活应用中成熟的“地图 + 当前范围列表”模式。

需要决定：

1. 地图还是列表作为发现页默认；
2. 动态地图失败时是否继续使用静态地图；
3. 地图与列表的数据关系；
4. 地图拖动时是否查询新的公开 POI；
5. 如何在生产故障或额度风险时止血。

## 决策

### 1. 动态地图默认

发现页没有 view 参数时默认进入动态地图。view=list 表示用户明确选择完整列表。旧 view=map 链接继续兼容，但新链接不必写该参数。

### 2. 列表是唯一地图降级

不再建设或调用静态地图。动态地图出现配置、鉴权、网络、超时、运行时或功能开关错误时，当前会话直接切换到可操作的完整地点列表，并保留已加载地点与筛选。

### 3. 单一授权数据集

地图 Pin 与完整列表来自同一个 FilteredSet；当前范围抽屉来自 FilteredSet 和地图 bounds 的交集。它们不能分别查询、分别分页或分别实现权限。

### 4. 只展示 Foodprint 推荐地点

地图只呈现当前有效小组中 active 且已有正向 current_opinion 的地点。候选、dismissed、archived、inactive_no_marks、其他小组地点和高德公开 POI 均不成为 Foodprint Pin。

### 5. 地图移动只改变视野

拖动和缩放不触发高德 POI 搜索、周边搜索或数据库写入。moveend / zoomend 后只在浏览器内从 FilteredSet 计算 ViewportSet。

### 6. 底部地点抽屉

未选 Pin 时也保留可上拉抽屉，显示“当前范围 · N 家”；点选 Pin 后显示地点卡片；继续展开后显示当前范围列表。

### 7. 服务端功能开关

增加 DISCOVERY_DYNAMIC_MAP_ENABLED。false 时列表默认、不下发 JS Key、不加载地图 SDK、不调用静态地图。它是生产止血和额度保护手段。

### 8. Pin 视觉另设批准门禁

技术结构可以先使用临时 Pin；正式发布前必须提供 3–5 套真实底图方案，并由项目负责人选定。

2026-08-13 补充决议：五套方向探索完成，项目负责人选定 B「餐盘定位圆章」。正式版本使用确定性 SVG 重绘的一 / 二 / 三层小碗、默认 / 选中、聚合和蓝色用户位置状态；唯一实施规范为 `docs/design/v2-3-map-pins/final/README.md`。此后实现不得继续使用临时 Pin，也不得把 ImageGen 概念图作为运行资产。

## 原因

- 地图默认最直接表达“共同美食地图”的产品价值。
- 可操作列表比静态截图更诚实、更轻、更可访问，也不会再维护一条独立静态 API 链路。
- 单一数据集能从结构上避免地图与列表数量、筛选和权限不一致。
- 不查询公开 POI 能保持邀请制、小组推荐、真实到访的产品边界，也控制高德调用量。
- 本地 ViewportSet 计算能在当前私域数据规模下提供即时交互，不需要引入复杂空间后端。
- 服务端开关比代码回滚更适合供应商故障与额度止血，又不会把开关暴露成可被浏览器绕过的配置。

## 被否决的方案

### 列表默认、地图可选

否决原因：不能实现本次“先把共同地图作为主界面上线”的产品目标。列表仍保留为平级切换和故障降级。

### 动态地图失败后显示静态地图

否决原因：用户明确认为没有必要；静态图不能拖动，继续维护 Edge Function、静态额度、图片请求和第二套故障链路，价值低于直接列表。

### 地图与列表分别请求

否决原因：容易出现分页上限、时序、权限和筛选差异，无法满足“同一组数据”。

### 拖图时搜索高德附近餐厅

否决原因：会把 Foodprint 变成公开 POI 浏览器，混淆“朋友推荐”与“附近商户”，增加调用、配额、许可和数据治理风险。

### 把所有地点、照片和详情一次加载

否决原因：地图需要全部轻量点位，但不需要全部私有图片和完整时间线；一次加载会恶化 V2.2 正在治理的首屏与私有媒体性能。

### 浏览器公开功能开关

否决原因：NEXT_PUBLIC 开关通常需要重新构建且可被客户端观察；服务端开关能够在容器重启后止血，并决定是否向页面提供 Key。

## 结果与代价

正向：

- 发现页心智更清楚；
- 地图、列表、抽屉一致性可测试；
- 动态地图故障时仍能找店；
- 静态地图相关代码和远端函数最终可退役；
- 后续替换 Pin 或地图供应商时，上层产品状态不必重写。

代价：

- 需要新增完整且轻量的 V2.3 发现索引，不能复用当前最多 20 条的读模型；
- 需要认真处理地图实例生命周期、聚合 ID 映射、bounds、抽屉手势和安全边距；
- 地图默认会增加 JS API 初始化量，必须监控免费额度；
- 生产仍依赖高德 JS API、域名白名单和同源安全代理；
- 正式上线多一个 Pin 视觉批准门禁。

## 迁移与回滚

- 新增向前兼容 RPC；保留旧 V2.2 RPC。
- V2.3 移除静态地图运行引用。
- 远端 amap-static-map 在 7 天应用回滚窗口内可以保留但不得被 V2.3 调用；稳定后退役。
- 首选回滚为 DISCOVERY_DYNAMIC_MAP_ENABLED=false，使发现页回到列表。
- 必须回滚应用时使用上一稳定容器镜像；不删除新数据库函数。

## 复核触发条件

出现以下任一情况需重新评审，不得由实现者自行改变：

- 高德账户主体或许可用途变化；
- 月初始化量持续逼近免费额度；
- 地图 ready 成功率长期不达门槛；
- 单组地点接近 2,000，需要空间分页；
- 真实用户明确更偏好列表默认；
- 需要显示候选或公开 POI；
- 更换地图供应商；
- 需要保存 / 分享地图视野或用户位置。

复核不自动意味着恢复静态地图；静态地图若再次提出，必须作为新的产品决定。
