# ADR 2026-07-30｜V1.3.3 地点与内容管理边界

> 状态：已拟定，随 V1.3.3 产品稿批准后生效
> 适用范围：小组地点、到访记录、照片、去试试候选和治理审计

## 背景

地点被成员首次推荐并进入“发现”后，目前缺少 Owner/Admin 的地点级管理入口。作者虽可删除自己的到访，Owner/Admin 也已有隐藏到访或照片的底层能力，但缺少二次确认、集中列表、恢复路径和一致的审计规则。“删除地点”“删除到访”“移除候选”如果共用一个垃圾桶概念，会造成共享 POI、历史记录和跨小组数据被误删的风险。

## 决策

| 对象 | 产品动作 | 数据行为 | 恢复规则 |
| --- | --- | --- | --- |
| 当前小组已推荐地点 | 下架地点 | 仅将当前 `group_places` 行设为 `archived`，保留 `places` 主数据和所有历史关联 | Owner/Admin 可恢复 |
| 作者自己的到访 | 删除这次到访 | 软删除到访及关联照片访问，并重算作者在该地点的 current opinion | 产品 UI 不提供恢复；按既有保留和清理规则处理 |
| 他人的到访或照片 | 隐藏内容 | Owner/Admin 填写原因后治理隐藏，不改写原文、评分或标签 | Owner/Admin 可恢复显示 |
| 去试试候选 | 移除候选 | 将 pending 候选软处理为 dismissed，并记录处理类型、原因和操作者 | 仅创建者移除或管理员移除可在通过冲突检查后恢复 |

## 权限边界

1. Owner 和 Admin 都可以下架/恢复小组地点、隐藏/恢复组内到访和照片、处理组内 pending 候选。
2. Member 只能删除自己的到访/照片，以及编辑或移除自己创建的 pending 候选。
3. 只有 Owner 可以查看其他成员邮箱、管理成员角色和账户状态；地点与内容治理不会扩大 Admin 的账户权限。
4. 产品 UI 不向任何角色提供物理删除 `places`、整组历史或审计记录的能力。
5. 所有权限由服务端根据当前 active membership 判定，不能依赖客户端按钮是否显示。

## 交互边界

1. 发现、地点详情和去试试卡片只提供 `···` 管理菜单；视觉图标可小，触控区域不得小于 44 × 44px。
2. 地点下架、作者删除到访、管理员隐藏内容和移除候选均须经过二次确认。
3. 地点下架和管理员治理原因必填，长度 1–280 字；确认框必须说明影响范围与恢复方式。
4. “我的”增加 Owner/Admin 专属的“地点与内容管理”，集中展示上架中、已下架、候选和已隐藏内容。
5. 危险操作不在普通浏览卡片上直接显示红色垃圾桶，避免误触和把“下架”误解为永久删除。

## 数据与审计后果

1. 下架只影响当前小组；其他小组使用同一 `places` POI 不受影响。
2. 删除作者到访后，必须在同一事务中用其最新剩余快照重建 current opinion；没有剩余到访则移除其 current opinion。
3. 地点不再有任何 current opinion 时进入 `inactive_no_marks`，而不是 `archived`。
4. Owner/Admin 隐藏他人内容不改写其 current opinion，继续遵守 V1.3 隐私治理 ADR。
5. 下架、恢复、删除、隐藏和候选处理均写入 audit log，记录 actor、时间、对象、前后状态和适用原因。
6. 历史数据不伪造操作者；缺少治理来源的旧行明确显示为历史处理记录。

## 不在本决策中的事项

- 地点主数据永久删除或跨小组合并；
- 批量清空小组历史；
- 公开举报大厅、公开处罚原因或公开负面榜单；
- 管理员修改成员原文、推荐强度或四维标签；
- 自动审核、人脸识别或基于图片内容的机器决策。

## 生效方式

本 ADR 与 `docs/specs/2026-07-v1-3-3-mark-form-and-management.md` 一并批准。若未来需要永久删除共享地点、扩大 Admin 的账户权限、公开治理记录或允许管理员修改成员观点，必须新增 ADR，不得在编码阶段自行扩展。
