# 食迹 Foodprint｜产品路线图

> 更新日期：2026-08-18
> 用途：说明版本先后、依赖、进入条件与完成条件；不替代每个版本的 Spec。

## 版本状态

- 已关闭：已发布且完成约定验收。
- 已批准，待开发：产品与技术范围已经确认，可按交接单进入实现。
- 仓库实现完成，待真实地图／真机／生产验收：本地代码、测试和构建已完成，外部环境证据尚未完成。
- 待批准：范围已梳理，项目负责人尚未批准进入开发。
- 待立项：方向确认，但还未达到可开发的规格完整度。

V2.3 的开发工作已于 2026-08-14 收束归档。2026-08-16 的正式使用反馈已建立为 V2.4；仓库内的 ICP 门禁、照片 canonical fallback、正式 Pin 映射、地图优先布局、统一筛选状态和三状态面板已经实现并通过本地检查。2026-08-18 的 V2.4 真机验收继续发现手机照片上传失败、筛选浮层裁切、定位按钮与提示遮挡，已独立建立 V2.4.1 开发交接。V2.4 当前仍待真实高德、真机和生产验收；V2.4.1 已完成仓库实现和本地门禁，仍待真实设备、干净库重放、生产小样本与 24 小时观察，不代表线上已经修复。

## P0｜地图可靠性与安全基线

已完成正式发布与验收：Production 使用精确 Origin 白名单，两个 Supabase Edge Function 已部署，地点检索、地点建议与地图降级均在正式地址验证通过。P0 不扩展用户功能，交付受控 Origin、AMap 域名白名单检查、错误降级、健康检查、监控和操作手册。详见 specs/2026-07-p0-amap-reliability-security.md。

## V1.2｜发现与去试试

信息架构升级：将首个“地图”入口更名为“发现”；新增“去试试”候选清单和轻量加入入口；保留“下回吃”作为已推荐地点的个人收藏。候选餐厅经真实体验后只会进入“发现”或从候选列表消失，不产生公开避雷内容。详见 specs/2026-07-v1-2-discovery-try-list.md。

## V1.3｜记一顿与地点详情

把单次标记拆为首次完整记录和后续轻量到访；地点详情形成图文时间线；引入三级小碗、当前观点汇总及“好在哪儿”图标计数。饭后聊仅做图文记录流，不做点赞、评论或回复。详见 specs/2026-07-v1-3-record-a-meal.md。

### V1.3.x 体验小迭代

- **V1.3.1｜发现页卡片、筛选与视觉一致性：** 开发完成，待 Preview 与 320 / 375 / 390px 人工验收；发布前需应用商圈缓存 migration 并部署更新后的高德 Edge Function。
- **V1.3.2｜去试试流程：** 下一阶段，尚未进入开发；不得混入 V1.3.1 发布范围。
- **V1.3.3｜记一顿清晰度与地点内容管理：** 完整产品开发稿和 D 方向四维图标资产已完成，待批准后编码；包含 C 方向表单、全局四维图标、Owner/Admin 地点下架与恢复、作者到访删除、管理员内容隐藏/恢复、候选软移除和“我的”集中管理。

## V1.4｜字体与文案收束

在不改变地点、权限、推荐与数据逻辑的前提下，统一全站为“思源黑体 SC（功能）+ 站酷小薇体（少量情绪标题）”两字体体系，并完成所有固定用户文案、状态与操作反馈替换。文案已于 2026-08-03 批准，工作稿与正式 [V1.4 开发交接单](./FOODPRINT_V1_4_DEVELOPMENT_HANDOFF_2026-08-03.md) 已归档；当前进入实现与待验收阶段。

## V2｜大陆部署与地图体验

V2-A 已将 Next.js 应用运行环境和正式入口迁入腾讯云，并以 `foodprint.com.cn` 作为唯一正式域名；当前 Supabase 数据平面继续承担 Auth、PostgreSQL、Storage、RLS、RPC 和 Edge Functions。V2-A 当前进入稳定期，剩余工作是完整业务回归、7 天观察、恢复演练和 GitHub Actions 腾讯云发布管道。动态地图与 Supabase 数据平面迁移分别作为后续工作，不自动混入本次切流。详见 [V2 开发交接](./FOODPRINT_V2_MAINLAND_DOMAIN_MIGRATION_DEVELOPMENT_HANDOFF_2026-08-05.md) 与 [V2 规格](./specs/2026-07-v2-mainland-maps-compliance.md)。

## V2.1｜低延迟与 PWA 用户体验

V2.1 针对 V2-A 上线后的真实体验反馈立项：减少公开页面和受保护页面的不必要远程认证、消除首页重复读取与用户触发的商圈回填、建立可缓存的 PWA 启动壳、改善页面转场反馈、补齐中国大陆真实网络下的性能指标。仓库内 P0/P1 开发已完成，但 2026-08-10 的再次真实使用仍出现约 10 秒桌面 PWA 白屏、页面跳转慢和用户照片加载慢，因此 V2.1 不能标记关闭，遗留效果问题进入 V2.2。详见 [V2.1 开发交接](./FOODPRINT_V2_1_PERFORMANCE_UX_DEVELOPMENT_HANDOFF_2026-08-06.md) 与 [V2.1 实现记录](./releases/2026-08-06-v2-1-performance-ux.md)。

## V2.2｜启动、跳转与私有图片性能

V2.2 以 V2.1 后的真实使用反馈和当前代码审计为输入：删除 `/launch` 到首页的自动完整文档跳转，建立真实的导航壳/关键内容完成指标和受控意图预取，按路由拆分认证、读模型、管理区与媒体阶段，为私有照片增加向前兼容的 thumbnail 元数据、批量短期签名和幂等旧图回填，并让 6.18MB 全量中文字体退出首屏关键链路。V2.2 继续禁止缓存私有 HTML/RSC/API/照片，不自动迁移 Supabase 数据平面；是否进入 V2-B 由优化后的分段 p75/p95 决定。详见 [V2.2 开发交接](./FOODPRINT_V2_2_PERCEIVED_PERFORMANCE_MEDIA_DEVELOPMENT_HANDOFF_2026-08-10.md) 与 [V2.2 实现记录](./releases/2026-08-10-v2-2-performance-media-implementation.md)。当前只代表仓库实现状态，不代表线上或真机门禁已通过。

## V2.3｜发现页动态地图

发现页默认进入高德动态地图，只展示当前小组已经真实推荐的地点；地图 Pin 与完整列表严格来自同一个授权数据集。用户可拖动、缩放、点选 Pin 查看底部地点卡片，也可在没有选中 Pin 时上拉“当前范围 · N 家”抽屉查看当前视野地点。动态地图失败或被运行开关关闭时直接切换完整列表，不再使用静态地图。正式开发还包括完整轻量发现索引、点位聚合、GCJ-02 定位、同源安全代理独立限流、匿名指标、已批准 B「餐盘定位圆章」资产接入和 7 天稳定观察。详见 [V2.3 产品规格](./specs/2026-08-v2-3-dynamic-discovery-map.md)、[技术交接](./FOODPRINT_V2_3_DYNAMIC_MAP_DEVELOPMENT_HANDOFF_2026-08-12.md)、[正式 Pin 规范](./design/v2-3-map-pins/final/README.md) 与 [验收清单](./acceptance/V2_3_DYNAMIC_MAP_ACCEPTANCE_CHECKLIST_2026-08-12.md)。

## V2.4｜地图优先体验与生产回归

V2.4 承接 V2.3 上线后的真实反馈。Stage 0–3 已在仓库实现并通过本地自动化门禁：ICP 备案恢复与构建验证、历史照片 canonical fallback、正式 Pin 稳定映射、列表 / 地图共享筛选、地图优先半透明叠层、三状态语义底部面板与手势隔离均已落地；Stage 4 的真实高德、真机、干净数据库 migration、生产验收与回滚证据仍待完成。演示稿中的临时 Logo、Pin、底部导航图标和示意底图不构成正式资产。详见 [V2.4 地图优先体验开发交接](./FOODPRINT_V2_4_MAP_FIRST_EXPERIENCE_DEVELOPMENT_HANDOFF_2026-08-16.md)。

## V2.4.1｜地图控件与照片上传修复

V2.4.1 承接 2026-08-18 的 V2.4 真机验收反馈。P0 是让常规 3–6MB 手机原图稳定完成浏览器预处理、私有上传和幂等补传，避免业务记录先成功但照片静默丢失；P1 是把地图筛选菜单移出横向 overflow 裁切容器，接入正式 ImageGen 透明 PNG srcset（SVG 回退），并让定位反馈跟随三状态面板实际高度。当前已完成 M0–M5 的仓库实现、自动化门禁、定位图标正式资产处理与实现报告；真实设备、干净库重放、生产小样本和 24 小时观察仍待执行。详见 [V2.4.1 开发交接](./FOODPRINT_V2_4_1_MAP_POLISH_AND_PHOTO_UPLOAD_RECOVERY_DEVELOPMENT_HANDOFF_2026-08-18.md) 与 [实现报告](./releases/2026-08-18-v2-4-1-map-polish-photo-upload-recovery.md)。

## V3｜视觉系统与精致表达

在不改变已验证产品逻辑的前提下，依据用户反馈统一视觉语言，落地定制小碗图标、字重与字体层级、配色、地点详情的纸张/便签式时间线、轻量照片轮播及无障碍和性能优化。V3 必须等待 V2.2 启动、导航和媒体链路以及 V2.4.1 地图 / 照片主流程稳定，避免用视觉重做掩盖未解决的可靠性问题。详见 specs/2026-07-v3-editorial-visual-system.md。

## 版本完成条件

每个版本只有同时满足已批准 Spec 的验收标准、自动化检查、角色和真机人工验收、migration/回滚/运行配置记录、发布记录与已知限制说明时，才可标记为已关闭。
