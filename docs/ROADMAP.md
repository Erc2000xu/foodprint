# 食迹 Foodprint｜产品路线图

> 更新日期：2026-07-28
> 用途：维护版本状态、产品方向、依赖与进入条件；不替代版本 Spec。

## 状态定义

- **已关闭**：已发布并完成约定验收。
- **体验观察中**：已发布且核心人工验收通过；保留真实使用反馈的修复入口，尚不进入下一大版本开发。
- **待立项**：方向已确认，但尚未有批准的 Spec，不开始编码。
- **候选**：值得讨论，优先级和范围均可调整。
- **延期运维**：不阻塞产品版本，待运行需要或明确排期时处理。

## 已完成基线

| 版本 | 状态 | 已达成结果 |
| --- | --- | --- |
| MVP / V1.0 | 已关闭 | 邀请制共同餐饮地图、真实标记、照片、发现、PWA、导出与运行加固 |

### V1.1.2｜管理页体验修复

**状态：范围已获项目负责人确认，待 Codex 实施前验证与开发**

针对 V1.1.1 Preview 的实际体验反馈，拟统一 `Owner` / `Admin` / `Member` 角色用语，修复成员卡片中邮箱被操作按钮挤压的问题，在成员区块说明注册与自动入组流程，并将数据导出移到管理页底部。此补丁完成并通过回归后，连同 V1.1.1 一起关闭。详见 [V1.1.2 Spec](specs/2026-07-v1-1-2-admin-polish.md)。

## 未来版本方向

### V1.2｜让“找什么、为什么推荐”更清楚

**状态：待立项**

目标是解决首页、发现页和地点列表之间的重复与信息不足，使成员更快理解当前小组有什么值得去、如何按意图找到它。

拟讨论方向：

- 首页从 Phase 0 欢迎内容升级为真实地点、近期活动、推荐和个人待办的摘要；
- 重构“发现”在信息架构中的角色，消除与首页列表的重复；
- 完善区域、菜系、场景、评分等筛选的空状态、排序和可分享 URL；
- 为历史地点建立受控的信息完善路径，避免猜测或批量抓取地理数据。

**进入开发前必须确定：** 首发城市与数据边界、发现页的唯一职责、首页优先展示的信息、筛选排序规则、每个界面的验收截图/原型。

### V1.3｜让地图成为可靠的探索界面

**状态：候选，依赖 V1.2 的信息架构结论**

目标是在不牺牲稳定性、隐私和高德合规边界的前提下，评估并实现真正有价值的地图探索体验。

拟讨论方向：

- 可缩放、可点按、与列表联动的互动地图；
- 地图视窗、点位聚合和地点详情抽屉；
- 互动地图不可用时回退至当前静态地图与列表；
- 高德加载稳定性、域名白名单、配额、服务端代理与真机验收。

**进入开发前必须确定：** 互动地图技术验证成功、加载/错误降级策略、配额影响、个人精确位置的处理边界、移动端交互原型。

### V2｜让共同记录可以长期成长

**状态：候选**

目标是把已验证的“小组共同记录”从功能集合提升为稳定、可维护的长期空间。

拟讨论方向：

- 小组治理的补全：Owner 转移、邀请历史导出、必要的审计与数据治理；
- 地点资料质量：受控更新、去重、来源和历史信息的可追溯；
- 更完整的个人与小组回顾，例如收藏、到访和推荐的时间线；
- 备案完成后的腾讯云切流评审与生产可靠性建设。

**进入开发前必须确定：** 真实小组使用数据、治理痛点、数据迁移/备份演练结果，以及哪些能力必须服务“可信共同记录”。

### V3｜让发现建立在可信关系上

**状态：候选**

目标是让成员更自然地从朋友的真实体验中获得灵感，而不是变成不透明的餐厅内容流。

拟讨论方向：

- 基于小组真实记录的主题、场景或时间线浏览；
- 清晰可解释的推荐与筛选，而非黑盒推荐；
- 更适合分享、回顾和共同策划的轻量协作能力。

**进入开发前必须确定：** 使用频率与隐私反馈、推荐解释规则、反骚扰/权限边界，以及对“公开化”的明确取舍。

### V4｜可持续扩展与平台成熟

**状态：远期探索**

目标是在产品核心价值已被长期使用验证后，再讨论多城市、多小组、更丰富的服务能力与基础设施演进。

此阶段不预先承诺具体功能。任何扩展必须先证明它不会破坏真实体验、朋友信任、数据合规与低运营复杂度。

## 延期运维事项（不阻塞版本）

- 独立 SMTP、邮件模板与投递监控；
- Owner/Admin 的邀请历史导出界面；
- 高德配额与使用许可的定期复核；
- ICP 完成后的腾讯云迁移评审与切流演练。

## 每个版本的完成条件

只有同时满足以下条件，版本才可标记“已关闭”：

1. 已批准 Spec 中的验收标准全部完成；
2. 必需的自动化检查（类型、Lint、测试、构建）通过；
3. 涉及权限、数据或部署时，完成对应角色与环境的人工验收；
4. migration、回滚和运行配置已记录；
5. 发布记录说明已完成内容、已知限制和后续事项。
