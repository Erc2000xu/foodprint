# 食迹 Foodprint｜产品总览

> 更新日期：2026-08-12
> 状态：当前长期产品基线。具体开发以已批准的版本 Spec 为准。

## 1. 产品是什么

食迹是一个邀请制的小范围美食记录与分享应用：先为自己留住吃过、愿意再去的地方；再让朋友看见彼此的真实体验；最后让一顿饭自然延伸为生活中的相聚、回忆与灵感。

它不是开放式餐厅黄页，也不是公开的差评或避雷平台。发现页只呈现经过真实到访、被判定为值得推荐的地点。

## 2. 核心价值与用户层次

| 层次 | 用户要完成的事 | 食迹提供的价值 |
| --- | --- | --- |
| 为自己 | 记录吃过的好店，留住当时的感受 | 一份可回看的个人美食地图 |
| 与朋友 | 互相分享可信的地点和菜品 | 真实、私密、无需筛选噪音的推荐 |
| 因一顿饭相聚 | 从地点出发回看生活片段 | 轻盈而不打扰的饭后记录空间 |

## 3. 信息架构与产品语言

产品语言应自然、温暖、现代、生活化；不使用冷冰冰的工作流或审核口吻，也不过度口语化或堆砌文学表达。

| 一级入口 | 作用 | 当前确认用语 |
| --- | --- | --- |
| 主发现 | 默认在可拖拽的共同地图上浏览已被真实推荐的地点，也可切换同一组地点列表 | 发现 |
| 候选地点 | 收藏尚未亲自验证、准备去试的餐厅 | 去试试 |
| 记录到访 | 新增真实到访与一顿饭的感受 | 记一顿 |
| 小组记录流 | 浏览朋友的图文到访记录 | 饭后聊 |
| 个人空间 | 管理个人资料、收藏和小组设置 | 我的 |

个人对已推荐地点的收藏清单命名为“下回吃”。它与“去试试”严格区分：前者是已被认可、自己下次想去的地点；后者是尚待真实体验的候选地点。

## 4. 产品原则

1. 真实体验优先：候选地点不是推荐；只有真实到访并愿意推荐的地点才进入发现。
2. 小圈层优先：先服务高信任朋友群，不追求公开内容流或高频互动。
3. 为自己，也为朋友：一人食同样成立，分享是自然延伸而非使用前提。
4. 温度来自真实记录：评价不以公开星级竞争为核心，而以“下次还想不想去”的真实意愿表达。
5. 隐私、安全与合规先于便利：最小化收集个人信息，严格执行小组权限和访问控制。
6. 小步交付、可验收、可恢复：重要能力先有 Spec、迁移方案、回滚路径和发布检查。

## 5. 已确认的地点生命周期

1. 用户在“去试试”通过地点检索加入候选餐厅，可选填从哪里听说、为什么想试。
2. 候选餐厅显示在“去试试”列表；它不是发现页内容。
3. 有人真实到访后，先判断是否值得推荐。
4. 值得推荐：完成一顿记录，地点进入“发现”，形成可持续累积的详情页与时间线。
5. 不值得推荐：从“去试试”消失，不公开展示，也不进入“发现”；后端保留最小化的验证与去重记录。
6. 同一用户可多次到访同一地点；时间线保留每次记录，而该用户仅以其当前观点参与地点总体推荐强度。

## 6. 推荐表达

前端不显示传统五分星与小数分。每位到访者以三级小碗表达当前推荐意愿：

| 内部值 | 对用户的表达 | 图形 |
| --- | --- | --- |
| 1 | 值得去 | 一层小碗 |
| 2 | 想再去 | 两层小碗 |
| 3 | 会专门去 | 三层小碗 |

地点汇总以所有有效用户当前观点的平均值计算，再按四舍五入映射为一至三层小碗；卡片显示小碗与到访人数，而非暴露小数分。地点好在哪里，以图标加人数汇总呈现，首批标签为“吃得香、坐得住、聊得开、花得值”。

## 7. 当前生产基线

当前仓库与生产能力已经跨越 V1.1.2：邀请制注册、小组成员与权限、发现 / 去试试生命周期、重复到访、地点详情、饭后聊、私有照片缩略图、PWA、腾讯云与 foodprint.com.cn 已形成当前基础。具体线上完成状态以 ROADMAP.md、版本交接和验收记录为准。

V2.3 已批准把动态共同地图作为发现页默认主界面：地图、完整列表与当前视野抽屉共享同一组小组推荐数据；地图故障直接切完整列表，不再使用静态地图。该段描述的是已批准产品基线，只有完成 V2.3 验收后才代表已生产关闭。

地图 Pin 使用 2026-08-13 已确认的 B「餐盘定位圆章」：一 / 二 / 三层小碗继续对应“值得去 / 想再去 / 会专门去”；选中态通过放大与橙红外圈表达，聚合显示地点数，用户位置使用独立蓝色圆点。正式资产与尺寸状态以 `docs/design/v2-3-map-pins/final/README.md` 为准。

## 8. 不变技术约束

- 正式应用以 https://foodprint.com.cn 和腾讯云运行环境为唯一生产入口；域名、TLS、Origin、Auth 回调和 PWA 配置变更须按发布手册回归。
- 数据库、RLS 与 RPC 的上线变更只新增向前兼容 migration，生产不做破坏性回滚。
- 高德 Web Service Key、Supabase 服务密钥及生产凭据只存于受控 Secret，绝不进入 Git 或浏览器。
- 高德地点数据只在许可、用途和配额允许范围内使用，不做批量抓取、再分发或自动付费。

运行、地图与安全基线分别见 OPERATIONS.md、AMAP_OPERATIONS_RUNBOOK.md、AMAP_FREE_TIER_POLICY.md 与 SECURITY_COMPLIANCE_BASELINE.md。
