## 二、建议准备的验收数据

- [ ] 一家有真实竖图的地点和一家无照片地点。
- [ ] 一家名称或地址较长的地点。
- [ ] 一家有三道以上推荐菜的地点。
- [ ] 一家有新版“好在哪儿”数据的地点；若小组数据允许，最好覆盖四个维度。
- [ ] 一家只有旧版“适合场景”、没有新版观点数据的历史地点。
- [ ] 一个已加入“下回吃”的地点和一个未加入的地点。
- [ ] 一家高德有真实商圈返回的地点，以及一家暂未返回商圈的地点。

## 三、移动端视觉与卡片

分别在浏览器响应式模式检查 **320px、375px、390px**：

- [ ] 页面没有横向滚动条，三个筛选按钮和浮层不超出右侧。
- [ ] 照片框始终为 3:4 竖向比例，真实照片居中裁切，不被拉伸。
- [ ] 无照片地点显示统一占位，没有伪造餐厅照片。
- [ ] “下回吃”位于卡片上层，不再独占底部一整行。
- [ ] 未收藏显示青绿描边爱心和“下回吃”；已收藏显示红色高对比状态，且两种状态都有文字。
- [ ] 长地点名最多两行，不遮挡收藏控件、推荐等级或照片。
- [ ] 卡片只显示当前一个小碗等级，没有 emoji，也没有同时出现三个等级。
- [ ] 等级文字正确：`值得去 / 想再去 / 会专门去 · N 位朋友吃过`。
- [ ] 四项“好在哪儿”均以固定徽记、文字和人数显示；所有非零项都出现，窄屏可自然换行。
- [ ] 旧场景只显示为低优先级 `适合：…`，不会伪装成“好在哪儿”。
- [ ] 推荐菜最多预览两道；三道以上显示“等 N 道”，进入详情后仍可看到完整菜品。

## 四、位置与商圈

- [ ] 历史 `city=北京市, district=北京市顺义区` 显示为 `北京市 · 顺义区`，没有“北京市 · 北京市顺义区”。
- [ ] 发现卡和地点详情的位置文案一致。
- [ ] 高德返回真实商圈时显示在城市、行政区之后；高德未返回时整段隐藏，不出现空标签或猜测名称。
- [ ] 新记一顿并新增地点后，商圈补齐失败也不影响保存成功和发现列表展示。
- [ ] 打开发现页后，历史地点会逐批补齐；一次最多处理三条，不出现短时间大量请求。
- [ ] Supabase 表 `place_amap_business_area_cache` 中能看到 `success / not_found / temporary_failure` 等实际结果；临时失败存在下一次重试时间。

## 五、搜索

逐项用当前小组真实数据搜索：

- [ ] 餐厅名。
- [ ] 推荐菜。
- [ ] 菜系。
- [ ] 行政区，例如“顺义区”。
- [ ] 地址中的文字。
- [ ] 旧版场景，例如“朋友聚会”或“快速简餐”。
- [ ] 搜索后页面明确显示当前搜索词和匹配家数。
- [ ] 清除搜索词标签后恢复未搜索状态。
- [ ] 搜索商圈或地铁并选择“高德地点建议”后，出现可移除的地点筛选标签和结果数。
- [ ] 行政区按行政区精确匹配；商圈按 3 公里、地铁按 1.5 公里筛选。
- [ ] 暂时阻断高德建议或使用无响应网络时，页面提示“地点建议暂不可用，仍已按站内内容筛选”，站内结果仍可用。

## 六、三个筛选浮层

- [ ] “按地点找”“按菜系找”“找灵感”一次最多展开一个。
- [ ] 点击另一个筛选按钮会直接切换浮层。
- [ ] 点击页面其他位置会关闭浮层。
- [ ] 键盘按 Escape 会关闭浮层。
- [ ] 完成一项选择后浮层关闭，按钮的 `aria-expanded` 状态同步。
- [ ] “找灵感”只包含记一顿表单的受控场景；不存在“下午茶”这一无效筛选。
- [ ] 320px、375px、390px 下浮层内容可滚动或换行，右侧不溢出。

## 七、回归与权限

- [ ] 列表 / 地图切换正常，筛选后的数量与地图点位一致。
- [ ] 从发现进入地点详情，再返回时搜索和地点筛选仍保留。
- [ ] “下回吃”添加和移除成功，刷新后状态不丢失。
- [ ] 普通 Member 可以读取自己小组地点的商圈展示。
- [ ] 另一小组成员不能通过直接请求读取本组地点的商圈缓存。
- [ ] 高德商圈服务失败时，城市、行政区、站内搜索、详情页和记一顿仍可使用。
