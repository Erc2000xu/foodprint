# 食迹 Foodprint｜视觉资产台账

> 建立日期：2026-07-29  
> 用途：在产品开发前统一确认需要生成、绘制、替换和复用的视觉资产，避免编码阶段临时使用 emoji 或风格不一致的占位图形。  
> 维护原则：任何新页面进入开发前，先检查本台账；新增视觉资产必须先登记、出方向稿、确认，再进入制作和接入。

## 1. 为什么需要这份台账

食迹同时包含三类视觉内容，不能用同一种方法处理：

1. **品牌型图像**：吉祥物、空状态、成功页插画、页面氛围图。适合先用 ImageGen 做方向探索，再保存项目内正式资产。
2. **产品语义图标**：三级推荐、“好在哪儿”、地点层级等。必须成组设计、语义稳定、跨页面复用；不能由每个页面临时画一套。
3. **功能型图标**：搜索、返回、关闭、定位、导航、爱心、展开等。应使用受控 SVG 图标组件，保证小尺寸清晰、状态可变色和无障碍，不使用生成式位图。

emoji 只能出现在用户输入的内容，或经过产品明确批准的轻松文案中；不得作为正式功能按钮、评分、地点分类和导航图标的默认实现。

## 2. 状态标准

每项资产按以下阶段推进：

`待定义 → 方向稿 → 已确认 → 已制作 → 已接入 → 已验收`

另外使用两个特殊状态：

- `待迭代`：已有资产正在使用，但风格、清晰度或语义需要重做。
- `保留`：已有资产符合当前方向，本轮不修改。

每项必须记录：资产编号、页面/场景、语义、制作方式、尺寸与变体、当前状态、文件位置、最后确认版本。

| slug | 中文 | 母稿 | 程序版 |
| --- | --- | --- | --- |
| `tasty` | 吃得香 | `public/icons/good-at/tasty-master.png` | `public/icons/good-at/tasty-ui.png` |
| `comfortable` | 坐得住 | `public/icons/good-at/comfortable-master.png` | `public/icons/good-at/comfortable-ui.png` |
| `good_for_chat` | 聊得开 | `public/icons/good-at/good-for-chat-master.png` | `public/icons/good-at/good-for-chat-ui.png` |
| `good_value` | 花得值 | `public/icons/good-at/good-value-master.png` | `public/icons/good-at/good-value-ui.png` |

- 母稿：1254 × 1254、透明 RGBA PNG，用于后续重新导出，不由页面直接加载。
- 程序版：256 × 256、透明 RGBA PNG，是 V1.3.3 页面唯一允许调用的文件。
- 视觉：深青绿描边、暖米白陶瓷/纸张、金色与少量橙色点缀；主体在安全画布内尽量饱满。
- 生成源、五套方向板和小尺寸 QA 保存在 `docs/design/v1-3-3-good-at-icons/`。
- 全局范围：凡展示四维评价，均通过同一 `GoodAtIcon` 组件调用；包括记一顿首次/再次到访、发现卡、地点详情、饭后聊，以及后续新增的四维汇总。
- 数据库和服务端只保存/返回四个 slug，不保存图片路径。
- 深青实心底会降低椅架对比度；选中态使用浅鼠尾草底、深青边框和勾选标记。

## 8. 开发门禁

1. 新需求评审时先登记资产编号，不允许直接在代码里决定图标。
2. 方向稿可由 ImageGen 辅助，功能型小图标优先使用 SVG；若产品明确确认带材质和轻立体感的位图路线，必须像 IC-01/IC-02 一样登记透明母稿、程序版、组件和适用范围。最终资产必须保存到项目，而不是只存在于对话或临时目录。
3. 已确认资产必须提供统一组件，页面只能调用组件，不能复制图片路径或自行换图。
4. 每个图标至少检查 320、375、390px 手机宽度以及 1×/2×/3× 屏幕缩放。
5. 每个非装饰图标必须配文字、可读标签或无障碍名称；不能只靠颜色区分状态。
6. 替换资产时保留版本记录，先更新台账，再更新代码；历史数据不得因为视觉升级无法显示。
7. 每次生成、重做或确认 UI/品牌图片后，当轮必须更新本台账中的状态、正式路径、尺寸/变体、适用页面、确认版本和下一步；不得只把文件放进项目而不登记。
