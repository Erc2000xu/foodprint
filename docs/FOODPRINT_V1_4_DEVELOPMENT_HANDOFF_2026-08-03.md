## 2. 已批准的字体方案

| Token | 字体 | 使用范围 | 实施要求 |
| --- | --- | --- | --- |
| `--font-ui` | 思源黑体 SC | 全站默认：导航、标题、正文、表单、地点名、地址、按钮、状态、用户内容和管理页 | 使用本地托管的 WOFF2/子集；保留版本与 OFL 文件 |
| `--font-display` | 站酷小薇体 | 每页至多一条短的品牌/情绪标题 | 只用于工作稿标记为创意的固定标题；不得用于按钮、输入、地址、日期、错误、隐私、动态地点名或用户笔记 |

### 2.1 创意字定稿位置

当前批准使用站酷小薇体的主要标题为：

- P01 发现：`今天想去哪儿吃？`
- P02 去试试：`想去的地方，先记在这里。`
- P03 记一顿：`把这一顿，好好记下来。`
- P05 饭后聊：`吃过以后，留下几句话。`

如果实际布局导致标题需要换行，优先调整字号、宽度和行高；不得把创意字体扩展到同页的功能文字。

## 4. 品牌化要求

App 用户界面不得出现第三方地图或地点服务品牌名称。开发时将下列技术事实包装成食迹自己的界面语言：

| 技术场景 | 用户可见写法 |
| --- | --- |
| 地点搜索结果 | `地点建议`、`搜索结果` |
| 行政区/商圈/地铁筛选 | `行政区`、`商圈 / 地铁` |
| 地点来源标签 | `地点信息` |
| 外部导航 | `导航去这里`、`查看地图位置` |
| 外部地图打开失败 | `地图暂时无法显示；你仍可在列表中查找地点。` |
| 地点搜索失败 | `地点搜索暂时没有响应，请稍后再试。` |
| 定位失败 | `无法使用定位，已按默认顺序显示。` |
| 管理页补充地点信息 | `这些信息由系统自动整理。` |

第三方服务名称可以继续出现在工程源代码、运行手册、政策和合规文档中，但不得出现在 App 的标题、按钮、标签、说明、错误、无障碍标签、照片替代文字或截图中。地图服务依法要求显示的版权标识属于合规标识，需单独按地图服务政策处理，不与品牌文案混用。

## 5. 语气验收标准

每个定稿句子都应满足：

- 有具体动作或具体场景，不使用“赋能、探索、沉淀、智能推荐、为你带来”等模板词。
- 生活化但不撒娇、不使用网络烂梗；不使用过度口语化的“啦、喔、随便挑一家吧”等语气。
- 有温度但不写成散文；功能说明、权限、隐私、后果和错误必须直接清楚。
- 同一概念使用同一词：`发现`、`去试试`、`记一顿`、`饭后聊`、`下回吃`、`隐藏`、`删除`、`下架地点`。
- 不将朋友的体验包装成绝对结论，不使用“最好、必吃、不会踩雷”等承诺。

## 6. 开发顺序

1. 在全局样式建立 `--font-ui` 和 `--font-display`，接入本地字体文件、加载回退和 `font-display` 策略。
2. 按工作稿 ID 替换应用壳和公共状态，再替换发现、去试试、记一顿、地点详情、饭后聊、我的、认证和离线页面。
3. 将可预期的服务错误统一映射到工作稿的中文反馈；不再直接显示数据库、RPC 或第三方服务原始错误。
4. 清理所有用户界面中的第三方地图/地点服务品牌字样；保留工程层的服务名称与合规版权标识。
5. 为创意标题接入 `--font-display`；检查动态地点名、用户内容、地址、按钮和错误没有误用创意字体。
6. 按 320、375、390 px 宽度检查标题换行、表单可读性、错误提示和 iOS 输入缩放，再做桌面端回归。

## 7. 不在本次交接范围内的事项

- 不改数据库字段、迁移、RLS、地点生命周期、推荐计算和成员权限。
- 不新增评论、点赞、回复、评分模型或社交互动。
- 不在未批准的情况下重新润色已定稿文案。
- 不把字体文件直接从外部 CDN 运行时加载；生产环境使用已核验授权的本地字体资源。
- 不因为字体接入而引入新的地图服务、追踪脚本或外部数据上报。
