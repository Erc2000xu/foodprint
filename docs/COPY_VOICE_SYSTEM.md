# 食迹 Foodprint｜品牌文案与语气台账

> 建立日期：2026-07-29  
> 用途：统一页面标题、情绪文案、操作提示、错误状态和成功反馈，避免不同迭代出现机械、冲突或过度解释的语言。

## 1. 文案分为三层

### A. 功能文字

按钮、标签、字段名和导航，例如“列表”“地图”“按当前位置找”“保存”。目标是准确、短、没有歧义，不追求文学性。

### B. 引导文字

解释功能、隐私和下一步，例如“位置只用于本次搜索，不会保存”。目标是降低疑虑，明确后果。

### C. 品牌/情绪文字

页面抬头、空状态、成功页和少量栏目标题，例如“今天想去哪儿吃？”。目标是有生活感、烟火气和人与人之间分享食物的温度。这一层才允许适度文学性。

三层不能混用：确认删除、权限、错误和数据后果必须使用直接的功能语言，不能为了“好听”而含糊。

## 2. 食迹的语气

- 像熟悉这座城、愿意分享一家好店的朋友。
- 温暖但不过度热情；精致但不端着；生活化但不使用网络烂梗。
- 多写具体动作和体验：去吃、坐坐、聊聊、路过、记下、带朋友去。
- 少写平台口号式大词：赋能、探索无限、发现美好生活、品质生活方式。
- 不制造压力，不用“必须打卡”“错过可惜”等营销措辞。
- 对真实推荐保持克制：朋友的体验是线索，不宣称“全网最好”或“绝对不会踩雷”。

## 3. 标点与用词

- 页面情绪标题可以使用问号或句号，但同一页面不要连续出现多个感叹号。
- 按钮使用动词开头，例如“导航去这里”“记下这顿”“加入去试试”。
- “去试试”是候选清单，不写成“收藏”；“下回吃”才是对成熟推荐地点的个人收藏。
- “记一顿”是产品正式名称；代码和文档不得误写为“记忆顿”。
- “地点进入发现”必须以完成真实体验和愿意推荐为前提。

## 5. V1.3.2 去试试文案建议

### 页面主区

- 栏目：`去试试`
- 主标题候选 A：`把想吃的，先记在路上。`
- 主标题候选 B：`有些店，先留个念想。`
- 主标题候选 C：`听说不错，找天去试试。`
- 推荐默认：保留现有 `把想吃的，先放在这里。`，等视觉方向确认后再决定是否替换。

### 说明层级

- 主说明：`记下朋友提过、路过看到，或一直想去的一家。`
- 次级规则：`亲自体验并愿意推荐后，它才会出现在发现。`
- 隐私提示：`暂不推荐的选择不会公开。`

### 操作

- 搜索：`搜索想去的地点`
- 定位：`按当前位置找`
- 导航：`导航去这里`
- 转正入口：`我去过了`
- 值得推荐：`值得推荐，记下这顿`
- 暂不推荐：`这次先不推荐`

## 6. V1.3.3 记一顿与内容管理文案

### 记一顿

- 真实推荐确认：`这是我亲自去过、也愿意推荐给朋友的地方`
- 准入说明：`首次收录只接受真实、正向的推荐。`
- 值得去：`在附近，会放心推荐`
- 想再去：`吃过还惦记，愿意再来`
- 会专门去：`值得特意安排一趟`
- 吃得香：`味道和出品让人满意`
- 坐得住：`环境舒服，愿意多待一会`
- 聊得开：`适合一起吃饭聊天`
- 花得值：`价格与体验相称`
- 照片提示：`建议上传 3:4 竖图，首页展示更完整；其他比例可能居中裁切。`

### 地点与内容管理

- 集中入口：`地点与内容管理`
- 地点操作：`下架地点 / 恢复地点`
- 作者操作：`删除这次到访`
- 管理员操作：`隐藏记录 / 隐藏照片 / 恢复显示`
- 候选操作：`移除候选 / 恢复候选`
- 下架后果：`下架后，这家店会从发现、地图和普通列表中隐藏。已有到访、照片和成员观点会保留，你可以在“我的—地点与内容管理”中恢复。`
- 隐藏后果：`记录会从普通小组视图隐藏，原文不会被改写。可以在管理后台恢复。`

管理类文字必须使用“下架”“隐藏”“移除”区分不同数据行为。只有作者处理自己的到访时使用“删除”；任何地点级按钮不得写成“永久删除地点”。

## 7. 文案工作流

1. 每个页面先列功能事实：用户能做什么、数据会发生什么、哪些内容公开。
2. 再分别写功能文字、引导文字和品牌文字，不能先写一句 slogan 再倒推功能。
3. 页面开发前把核心文案登记到本台账，状态为“待确认”。
4. 视觉稿中使用真实候选文案，不使用 lorem ipsum 或临时英文。
5. 验收时同时检查：是否准确、是否与其他页面同义、是否过长溢出、是否对非技术用户友好。
