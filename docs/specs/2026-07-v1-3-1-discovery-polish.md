# V1.3.1｜发现页卡片、筛选与视觉一致性

> 状态：开发完成，待 Preview 与 320 / 375 / 390px 人工验收（2026-07-30）
> 前置版本：V1.3 已完成开发，处于验收与体验优化阶段
> 范围：发现首页及其与旧数据、地点筛选相关的展示；不改变推荐汇总、到访记录和权限规则。

## 1. 本迭代解决的问题

1. 发现卡片的“下回吃”操作独占底部一行，导致卡片过高且信息层次松散。
2. 三级推荐强度被展示成重复的 emoji 小碗，难以一眼区分推荐等级，也不符合产品的定制视觉方向。
3. 行政区文本在历史地点与新地点上可能出现不同的拼接形式，且同一概念在不同页面存在手工拼接风险。
4. “好在哪儿”与旧版“场景”标签混在同一区域，用户无法判断它们是否代表同一类信息；新数据缺少标签时会退回旧标签，导致卡片前后不一致。
5. 搜索框、站内文字搜索、高德地点建议、行政区筛选和商圈/地铁半径筛选之间缺少可见的连接，用户无法确定搜索词如何影响结果。
6. 三个顶部筛选菜单会同时保持展开，浮层可超出窄屏可视范围；没有点击页面其他位置关闭的行为。

## 2. 已确认的产品规则（不改动）

- 发现只展示小组内已被真实推荐的地点；下回吃仅是对已推荐地点的个人收藏。
- 三级推荐强度仍是 `值得去 / 想再去 / 会专门去`，仍按每位朋友的一份当前观点汇总；本迭代只改展示，不改计算。
- “好在哪儿”仍是 `吃得香 / 坐得住 / 聊得开 / 花得值` 四个维度，每次到访最多选两项；地点卡展示的是当前观点的聚合人数，不是点赞。
- 旧版场景标签（例如“带外地朋友”“快速简餐”）仍保留为历史数据和“找灵感”的筛选条件；它们不等于“好在哪儿”。
- 地点城市和行政区以高德原始字段为准；展示只做重复前缀清理，不凭空补城市或改写历史地点数据。

### 2.1 本轮已确认的视觉决策（2026-07-29）

- 总体气质采用“安静的城市散步”：米白、浅鼠尾草绿、深青绿与吉祥物橙色为基础；路线元素仅作辅助视觉线索。
- 现有背地图的腊肠犬不进入每张餐厅卡；用于空状态、首次引导、提交成功和少量温和的情绪节点。
- 发现卡左侧照片框固定为**宽 : 高 = 3 : 4**的竖向比例，适配常见手机竖拍；图片使用居中裁切，不新增用户手动选择封面位置的步骤。
- “下回吃”保留爱心：未收藏时为青绿/浅绿色描边，已收藏后切换为红色实心或高对比红色状态；两种状态均有文字和无障碍说明，不能只依赖颜色。
- 四项“好在哪儿”均同时显示固定小图标、文字标签和人数计数。
- 正文、表单、地点名称和数字继续以清晰的无衬线字体为主；手写感只用于极少量栏目标题、引语或吉祥物场景，绝不用于地点名、筛选、价格、地址、长文和按钮，避免可读性、字体授权和加载性能问题。

## 3. 卡片视觉与信息规格

### 3.1 结构

- 保留左图右文的紧凑卡片。左图为固定 `3 : 4` 竖向照片框；无照片仍显示统一占位，不伪造餐厅照片，也不要求用户在上传时挑选封面位置。
- 顶部元信息统一为：`菜系 · 北京市 · 顺义区 · 商圈`。行政区显示统一通过一个共享格式化函数生成，历史记录中的 `北京市顺义区` 也显示为 `北京市 · 顺义区`。商圈仅在高德已返回真实数据时显示，未返回时整段隐藏，不留空位。
- 名称、人均、推荐强度、朋友人数为第一信息层。
- 推荐菜为独立的预览区，最多显示两道菜或两行；更多菜以“等 N 道”明确收束，不按纯字符硬截断。地点详情展示完整菜品清单。
- “下回吃”不与长菜名争夺同一行；改为卡片上层的紧凑爱心收藏控件，未收藏为青绿/浅绿、已收藏为红色。最终位置在下一张卡片稿确认后冻结。

### 3.2 三级推荐强度图标

- 制作三个独立、可缩放的图标资产，而非把同一个碗重复 1/2/3 次。核心隐喻为“这家很下饭，连干一碗 / 两碗 / 三碗饭”：
  - 一级：一只刚吃完的干净饭碗，保留一两粒饭粒；
  - 二级：两只随意但整齐叠放的空饭碗，保留极少的饭粒；
  - 三级：三只叠放空饭碗，表达“连干三碗”，但保持精致、温暖、可口，绝不表现成油污、残渣或脏水槽。
- 三个图标均采用有轻微花纹的圆形奖章/硬币外沿，内部为浅米白陶瓷、深青绿描边、少量橙色点缀；路线元素只在一个候选方向中作为极弱的辅助线索。
- 卡片只显示当前地点的一个对应图标和文字，例如 `会专门去 · 3 位朋友吃过`；不在一张卡里同时显示三个等级。
- 图标在卡片中应明显大于普通文字图标，但不能压缩名称或造成卡片增高。
- 本轮三级推荐图标保留高清透明 PNG 母稿，并提供独立的 256px 上线文件；页面统一通过 `BowlIcon` 组件调用，并设置完整文字说明。图标不会依赖设备字体或 emoji，在不同手机上保持相同外观。后续如需动态换色或极小尺寸，可再人工矢量化，不把“自动转 SVG”作为本次上线前提。

### 3.3 “好在哪儿”汇总

- 四个维度采用固定、彼此不同的线性小图标、文字和颜色：
  - 吃得香：餐具 / 绿色；
  - 坐得住：椅子 / 琥珀色；
  - 聊得开：对话气泡 / 紫色；
  - 花得值：硬币或价格符号 / 珊瑚色。
- 卡片展示为紧凑的“图标 + 文字 + 数字”计数，不做按钮、不产生社交反馈含义。所有非零维度都可展示；窄屏时允许自然换行，不允许横向被裁切。
- 不再把旧版场景标签伪装成“好在哪儿”。为保留旧资料，旧场景只在有值时作为低优先级 `适合：快速简餐 · 带外地朋友` 展示，且只占一行；若产品决定卡片更极简，可仅保留在详情页和“找灵感”筛选中。

## 4. 搜索和筛选规格

### 4.1 一个搜索框，两类可解释结果

搜索框允许输入：餐厅名、推荐菜、菜系、行政区、地址、商圈、地铁站和场景。

- **站内匹配**：匹配已推荐地点的名称、行政区/地址、菜系、场景、推荐菜和短评；输入或确认搜索后，列表立即显示匹配的地点数量和当前词。
- **高德地点建议**：仅为商圈、地铁站、行政区等位置提供辅助建议。选择后变成可见且可移除的地点筛选标签，例如 `行政区 · 顺义区 ×`；列表按行政区精确匹配，或按商圈/地铁的已说明半径匹配。
- 高德建议暂时不可用时，仍执行站内匹配，并明确说明“地点建议暂不可用，仍已按站内内容筛选”，不能只显示笼统的网络错误。
- 说明文案统一为：`可搜餐厅、行政区、商圈/地铁、菜系或推荐菜。` 不再暗示只有商圈和地铁站会影响结果。

### 4.2 顶部三项筛选

- “按地点找”：列出高德返回的行政区；商圈/地铁需通过上方搜索并选择建议，选中后必须显示筛选标签与结果数。
- “按菜系找”：保留现有受控菜系列表和多选逻辑。
- “找灵感”：只展示数据库和记一顿表单中真实存在的受控场景标签。当前写死但并不存在于数据字典的 `afternoon_tea` 必须移除或先补齐为完整的录入、迁移和筛选能力；本次默认移除，避免零结果筛选。
- 三个菜单改为单一受控浮层：一次最多展开一个；点击其他筛选按钮切换；点击页面空白处、按 Escape、完成选择后关闭。
- 不采用“鼠标一离开按钮就关闭”作为唯一规则：这会使桌面用户从按钮移动到菜单时无法选择，且移动设备没有悬停。桌面可在指针离开“按钮 + 浮层整体”后关闭；移动端以点击外部关闭为主，并同步 `aria-expanded` 状态。
- 所有浮层以窄屏画布为边界定位：右侧筛选从右对齐或采用全宽底部面板，内容可换行/滚动，绝不从屏幕右侧溢出。

## 5. 旧数据兼容

- 不修改、不删除历史 `city`、`district`、场景标签、旧评分或到访记录。
- 所有行政区展示改用共享格式化函数；修复的是展示层，不是用猜测值回填数据库。
- 历史记录映射出的三级推荐强度可继续显示新图标。
- 历史记录没有“好在哪儿”数据时，不伪造为零评价；显示已存在的 `适合` 场景信息，或按最终视觉稿隐藏该行。
- 新增地点和旧地点走同一张发现卡组件及同一格式化/图标映射，避免新迭代只影响新内容。

## 5.1 高德商圈归属（新增）

- 商圈的唯一权威来源为高德：餐厅由高德 `poiid` 与 GCJ-02 坐标确定后，服务端调用逆地理编码 `extensions=all`，读取该坐标返回的 `businessAreas`。
- 新增的商圈字段仅保存高德返回的名称、所属 `adcode`、中心点和查询时间，作为可刷新展示缓存；它不是食迹自建商圈库，不可手工录入、不可批量采集、不可作为对外数据分发。
- 历史地点按需、受节流地补齐；高德未返回商圈时不猜测“王府井”等名称，也不显示空白占位。
- 补齐队列覆盖所有有高德 `poiid` 或有效 GCJ-02 坐标的既有地点，不以记录创建版本区分。每条任务保存成功、未命中、临时失败三种状态；临时失败可重试，未命中在设定刷新周期后才能再次查询，避免重复消耗接口额度。
- 新地点在首次保存时尝试补齐，历史地点由后台分批补齐；发现卡和详情页始终读取同一份商圈缓存，因此新旧卡片不会分裂成两套样式。补齐未完成期间，缺失商圈的卡片只隐藏商圈段，城市和行政区仍正常显示。
- 既有 `geo_entities` 的种子商圈数据不得继续作为发现页或地点展示的权威来源；本迭代以停止读取/弃用为目标，不做破坏性删除。

### 6.2 使用项目内标准矢量图形，不使用 ImageGen

搜索、返回、关闭、展开/收起、列表/地图切换、清除筛选、定位、外链和“下回吃”爱心属于功能性图标。它们需要在 16–24px 下清楚、可变色并能正确表达点击状态，因此采用项目内受控 SVG，而不是生成式位图。爱心的未收藏/已收藏仍按青绿描边与红色实心呈现。

底部五个主导航图标属于整套品牌导航，现版本先继续使用，待卡片主体视觉冻结后单独做一次成组审查，避免本轮同时重画过多范围。

5. 对发现、地点详情、记一顿、饭后聊、去试试、我的等窄屏页面做 320px、375px、390px 宽度检查；重点检查长店名、长地址、四个标签、菜单、照片和底部导航。
6. 补充单元测试：位置格式化、搜索词/高德位置筛选、无效场景过滤；完成移动端人工验收。

## 8. 验收标准

- 卡片不再出现 emoji 小碗；三级推荐清晰可区分，卡片只展示实际等级。
- 下回吃不再独占卡片底部一行，也不与可能很长的推荐菜文字争抢同一行；卡片高度较当前版本明显收紧。
- 行政区在发现与详情页均统一为“行政区 · 市级 · 区级”，历史地点不因新版本而显示不同格式。
- “好在哪儿”与“适合场景”语义明确、不混用；旧数据不会消失或被伪造成新数据。
- 搜索“顺义区”等行政区时，用户可看到匹配结果；选择高德地点后可见筛选标签、结果数与清除方式。
- 顶部任一筛选菜单在 320px 至 390px 宽度内完整可见；点击外部即可关闭，键盘 Escape 也可关闭。
- 不存在于受控场景数据中的标签不会显示为可选筛选项。

## 10. 2026-07-30 实施记录

- 发现卡已统一为 3:4 竖图、左图右文；“下回吃”移动到照片上层，不再独占底部一行。
- 三级小碗继续通过 `BowlIcon` 统一调用，卡片文案改为“值得去 / 想再去 / 会专门去 · N 位朋友吃过”。
- 四类“好在哪儿”会展示全部非零项，使用固定语义徽记、文字、独立颜色和人数；无新观点时才显示低优先级“适合”历史场景。
- 推荐菜最多预览两道，更多内容显示“等 N 道”；详情页仍展示完整清单。
- 行政区与商圈统一走共享位置格式化；新增高德逆地理商圈缓存、成功/未命中/临时失败状态、退避重试和每次最多三条的历史补齐。
- 搜索词、高德地点建议、行政区/商圈/地铁筛选均进入同一 URL 搜索状态；页面显示当前词、地点标签、结果数和清除入口。

- 自动化检查：TypeScript、ESLint、13 个测试文件中的 36 项 Vitest 测试及 Next.js 生产构建通过。
