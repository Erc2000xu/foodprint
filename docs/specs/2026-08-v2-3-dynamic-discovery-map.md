## 1. 一句话定义

把“发现”改造成一张可以拖动、缩放和点选的共同美食地图：地图默认展示当前小组真正推荐过的地点；用户拉动地图时，底部抽屉同步列出当前视野里的地点；点选 Pin 时出现地点卡片；若动态地图不可用，系统无缝切换到使用同一组数据的完整列表。

这不是大众点评或美团的公开餐厅黄页。Foodprint 借用的是“地图探索 + 当前范围列表”的交互方式，而不是它们的公开商户数据、榜单、广告或全量 POI 模式。

## 2. 背景与本次决定

此前动态地图受 Vercel 域名、国内访问和高德 JavaScript API 安全代理配置影响，发现页暂时使用列表与静态地图方案。当前正式入口已经迁至 foodprint.com.cn，应用运行在腾讯云，高德 JavaScript API Key 可以绑定正式域名，JS 安全密钥也可以通过同源服务端代理使用，因此具备重新上线动态地图的基础条件。

V2.3 对之前方案作出以下最终取舍：

1. 动态地图是发现页默认主界面，不再把列表作为默认界面。
2. 列表是地图的平级切换视图，也是地图运行失败时的唯一产品降级。
3. 不再生成、不再展示、不再调用静态地图。
4. 地图 Pin 与完整地点列表使用同一个授权数据集和同一套筛选结果。
5. 地图只显示当前小组的已推荐地点，不显示“去试试”、已移除、已归档或其他小组地点。
6. 点选单个 Pin 后，地图底部出现地点卡片。
7. 即使没有点选 Pin，地图底部也有可上拉的地点抽屉，展开后显示当前地图视野中的地点。
8. Pin 使用已批准的 B「餐盘定位圆章」正式资产；1 / 2 / 3 层小碗分别表示“值得去 / 想再去 / 会专门去”，选择变化同时通过尺寸和橙红外圈表达。
9. 动态地图可以通过运行配置一键关闭；关闭后发现页默认列表，用于生产故障或配额风险控制，不需要代码回滚。

## 3. 目标

### 3.1 用户目标

- 打开“发现”后，第一眼看到朋友共同推荐过的地点分布。
- 通过拖动和缩放，自然探索不同区域，而不是先理解筛选器。
- 随时知道当前地图范围内有多少家推荐地点，并能拉开列表逐家浏览。
- 点一下 Pin 即可看到足够做决定的信息，再选择是否进入详情。
- 地图加载失败时仍能立即找店，不遇到空白页、死循环或无意义占位图。

### 3.2 产品目标

- 强化“共同美食地图”作为 Foodprint 的核心心智。
- 保持邀请制、已到访、正向推荐、小组私域的数据边界。
- 地图和列表不出现数量不一致、筛选不一致或权限不一致。
- 在不采购高德付费服务的前提下控制初始化次数、调用量和故障风险。
- 为后续视觉升级保留可替换的 Pin 渲染层，不把视觉资产写死在地图逻辑中。

### 3.3 V2.3 成功判定

- 真实账号在 foodprint.com.cn 打开发现页时默认进入可交互地图。
- 拖动、缩放、Pin、聚合、底部卡片和视野地点抽屉均可用。
- 同一筛选条件下，地图 Pin ID 集合与完整列表 ID 集合完全相等。
- 地图致命错误能够自动切到列表，已加载地点和全部筛选条件均保留。
- 线上不再产生静态地图请求。
- B「餐盘定位圆章」已经书面批准并完成正式资产；发布前通过真实高德底图与真机视觉验收。

## 5. 不可违反的产品约束

### 5.1 单一数据集

定义：

- 基础集合 BaseSet：当前登录用户的当前有效小组中，状态为 active、已经由真实到访形成正向推荐的全部地点；坐标质量不能用来悄悄删掉一个已推荐地点。
- 筛选集合 FilteredSet：在 BaseSet 上应用当前搜索、地区、菜系、场景、人均及其他已批准筛选条件后的结果。
- 视野集合 ViewportSet：FilteredSet 中，坐标位于当前地图可视边界内的地点。

必须始终满足：

- 地图上的单点和聚合所代表的地点 ID 并集 = FilteredSet 的地点 ID 集合。
- 切换到完整列表后展示的地点 ID 集合 = FilteredSet 的地点 ID 集合。
- 底部视野抽屉展示的地点 ID 集合 = ViewportSet 的地点 ID 集合。
- 列表顺序可以因当前排序规则而变化，但不得因此增删地点。
- 地图拖动只改变 ViewportSet，不改变 BaseSet 或 FilteredSet。
- 任何服务端截断、分页遗漏或权限不确定都不得伪装成“完整地图”。
- 动态地图只有在 BaseSet 全量读取完成、且其中每个地点都有合法 GCJ-02 坐标时才可进入 ready；否则整页进入完整列表，不能只少画坏数据对应的 Pin。

### 5.2 私域与生命周期

- 数据访问必须由后端根据 auth.uid() 和当前有效小组成员关系确定，不接受浏览器传入任意 group_id 来扩大范围。
- 仅 group_places.status = active 且符合发现页推荐定义的地点进入 BaseSet。
- pending、dismissed、archived、隐藏、软删除和其他小组数据必须排除。
- 成员被移出小组或会话失效后，下一次读取不得继续获得小组地点。
- 地图与列表不能各自写一套权限或生命周期过滤。

### 5.3 不做静态地图

- 地图失败时直接进入列表。
- 用户不能看到“静态截图看似地图、实际不能拖动”的中间状态。
- V2.3 新代码不得调用 amap-static-map。
- 旧静态函数只可在发布回滚窗口内保持远端待命，不能被 V2.3 页面请求；稳定期结束后按交接单退役。

## 6. 发现页信息架构

### 6.1 默认路由语义

- 访问发现页根地址且没有 view 参数时，默认视图为地图。
- view=list 明确表示列表视图。
- 旧链接 view=map 继续兼容，但等同默认地图；后续生成的新链接不必写 view=map。
- 搜索与筛选条件继续放在 URL 中，便于返回和分享。
- 选中 Pin、抽屉高度、地图中心、缩放级别和用户即时位置属于临时交互状态，不写入 URL。

### 6.2 地图模式视觉层级

从上到下：

1. 紧凑的发现页标题区，以及地图 / 列表切换。
2. 搜索框和三组核心筛选入口，作为地图上方的浮层或紧凑固定区。
3. 占据页面主要剩余空间的动态地图，不做成列表中的一张小卡片。
4. 地图右侧的定位按钮和必要的缩放 / 比例控件；不得与抽屉重叠。
5. 地图上的单点 Pin、选中 Pin、聚合 Pin和用户位置点。
6. 位于底部导航上方的地点抽屉。
7. 固定底部主导航。

地图必须是视觉主角。搜索与筛选可保持品牌化纸张 / 圆角质感，但不得遮挡大部分地图。地图控件、品牌浮层和高德法定标识不得相互覆盖。

### 6.3 列表模式

- 保留现有发现卡片的核心信息和当前筛选功能。
- 列表展示 FilteredSet 全集，而不是上一次地图视野的 ViewportSet。
- 从地图切到列表时保留筛选与排序；从列表切回地图时保留相同结果集合。
- 地图刚发生故障而自动切列表时，在列表顶部显示一次轻量提示和“重试地图”操作。

## 7. 地图初始化与视野规则

### 7.1 第一次进入

- BaseSet 为空：不加载高德 SDK；显示品牌化空状态“共同地图里还没有地点”和“记下第一家”，仍保留地图 / 列表结构。
- FilteredSet 有地点：地图加载成功后自动把全部筛选结果纳入安全视野，四周留出顶部控件、右侧按钮和底部抽屉的遮挡空间。
- 只有一个地点：以该地点为中心，使用适合街区浏览而不过度放大的级别。
- BaseSet 含无效、缺失、坐标系未知或超出中国有效范围的坐标：地图数据状态为 invalid_coordinates，动态地图不得初始化；完整列表继续显示全部地点，并在相应地点标记“位置待补充”。发布前必须修复存量数据；线上若再次出现，则自动进入列表并记录匿名数量，不能只少画一个 Pin。
- FilteredSet 为空：保持地图可操作，显示 0 家抽屉和“换个条件试试 / 清除筛选”，不把空结果当作地图故障。

### 7.2 筛选变化

- 每次搜索或筛选条件确定后，地图重新将新的 FilteredSet 纳入安全视野。
- 仅改变排序不改变 Pin 集合或地图视野；它只改变完整列表和抽屉列表的排列。
- 快速连续改变筛选时只执行最后一次视野调整，避免地图抖动。

### 7.3 用户拖动与缩放

- 用户可以单指拖动、双指缩放和使用地图原生缩放行为。
- 地图运动过程中不发起高德 POI 搜索，也不更新 URL。
- 在 moveend / zoomend 后合并成一次视野更新，重新计算 ViewportSet。
- 抽屉标题更新为“当前范围 · N 家”。
- 若已选地点仍在视野中，保持选中；若已经完全移出视野，清除选中并回到范围摘要。
- 地图运动不能触发 React 整棵页面重建或重复初始化高德实例。

### 7.4 定位

- 初次进入不得主动弹出系统定位权限。
- 只有用户点“定位”或选择“离我最近”时请求一次权限。
- 高德底图与地点坐标使用 GCJ-02；设备 GPS 坐标必须通过高德定位能力或官方坐标转换后再用于地图和距离排序。
- 精确位置只存在于当前页面内存，不写数据库、URL、localStorage、sessionStorage、日志或分析事件。
- 拒绝、超时或不支持定位时，地图和列表继续完整可用，并显示不带责备的提示。

## 8. Pin 与聚合

### 8.1 必要状态

最终视觉方案至少覆盖：

- 默认单点。
- 选中单点。
- 小、中、大三档聚合，或一套可随数量清楚变化的聚合规则。
- 用户当前位置点；它必须与推荐地点明显不同。
- 键盘 / 辅助技术可理解的可点击语义和至少 44 × 44 CSS px 的触控命中区域。

默认 Pin 不应塞入完整地点名称。地图上以清楚、克制、具有 Foodprint 识别度的符号为主；地点名称、推荐强度、朋友人数和推荐菜进入选中卡片或抽屉。

### 8.2 聚合规则

- 地点密集时使用高德 MarkerCluster 或经验证的等效聚合方案。
- 聚合数字代表其中 Foodprint 推荐地点数量，不代表高德公开 POI 数量。
- 点击聚合优先放大并把该聚合范围纳入安全视野。
- 达到最大缩放级别仍有同坐标 / 极近地点时，不继续无意义放大；展开抽屉并列出该聚合中的地点。
- 聚合拆分和合并不能丢失、重复或改变 FilteredSet。

### 8.3 已批准视觉与接入门禁

2026-08-13 已完成五套方向探索并由产品负责人选定 B「餐盘定位圆章」。V2.3 不再使用临时 Pin，也不得从 ImageGen 方向图裁切运行图像。正式规范、资产路径、尺寸、锚点、颜色、状态和高德接入合同以 [IC-08 正式资产规范](../design/v2-3-map-pins/final/README.md) 为唯一真相源。

正式实现必须满足：

1. `bowlStrength = 1 / 2 / 3` 分别使用一 / 二 / 三层小碗，并与“值得去 / 想再去 / 会专门去”一致。
2. 默认 Pin 为 40 × 45 CSS px；选中 Pin 为 48 × 54 CSS px；图形底部中心精确锚定经纬度。
3. 选中态同时改变尺寸与橙红外圈 / 尖角，不只靠颜色；选中 Marker 的层级高于默认 Marker。
4. 聚合数字动态显示 `1–99`，超过 99 显示 `100+`；数字代表 Foodprint 地点数。
5. 用户位置使用独立蓝色圆点，不得与推荐等级或选中态混淆。
6. 可点击 Marker 命中区至少 44 × 44 CSS px，并覆盖按下、键盘焦点与 `prefers-reduced-motion`。
7. 资产只从 `/icons/map-pins/` 本地 SVG 注册表调用；地图逻辑不得散落文件路径或使用概念图。
8. 发布前仍需在 320 / 390 / 430px、街区 / 城区 / 全城、高德远山黛等可用官方底图、密集点位和底部抽屉遮挡场景完成真实地图验收。

## 9. 点选地点与底部卡片

### 9.1 点选 Pin

- 点击单点后，将其设为 selectedPlaceId。
- Pin 进入明显选中态，并确保它位于不被顶部控件和底部卡片遮挡的安全区域。
- 抽屉自动进入“地点卡片”高度。
- 不立即跳详情，不改变地图缩放，不写 URL。

### 9.2 卡片内容

地点卡片应包括：

- 私有缩略图；无图时使用现有品牌占位，不加载原图。
- 地点名称。
- 行政区 / 商圈或简短地址。
- 小碗推荐强度和朋友到访人数。
- 最多一行代表性推荐菜或短评摘要；没有内容时不留空洞占位。
- “查看详情”主操作。
- 收藏状态可以复用现有能力，但不要求在 V2.3 新增一套地图专属收藏逻辑。

### 9.3 选中态退出

- 点击地图空白处：清除选中，抽屉回到范围摘要。
- 点另一个 Pin：替换选中地点，卡片原位更新。
- 在抽屉列表点一行：地图平移到该点、选中对应 Pin，并进入地点卡片态。
- 进入详情后返回：恢复筛选和地图模式；不强制恢复像素级中心、缩放或抽屉高度。

## 10. 当前视野地点抽屉

### 10.1 核心原则

抽屉始终存在于地图模式，不以“先点 Pin”为前提。它是地图与列表之间的桥梁，也是对地图上重叠、密集和不便点按地点的可访问补充。

抽屉采用“上拉展开、下拉收起”的底部 Sheet，位于底部导航之上。拖拽只从把手 / 标题区域开始，列表内容区域保持正常垂直滚动，避免与地图和列表手势冲突。

### 10.2 四个语义状态

| 状态 | 进入条件 | 主要内容 | 建议高度 |
| --- | --- | --- | --- |
| 范围摘要 peek | 地图已就绪且未选 Pin | 把手、“当前范围 · N 家”、展开提示 | 72–88px，加安全区 |
| 地点卡片 card | 点选单点 | 一张完整地点卡片与展开入口 | 约 200–240px，按内容自适应 |
| 半屏 half | 用户上拉或点标题 | 当前视野地点列表，可滚动 | 约 45–52dvh |
| 大屏 expanded | 再次上拉或点“展开全部” | 当前视野地点列表，地图保留一条可感知区域 | 顶部不得越过紧凑标题 / 搜索安全线 |

具体像素由实现时根据底部导航、safe-area-inset-bottom、字号和真实设备校准；语义状态不得因设备高度被删除。

### 10.3 未选 Pin 时

- peek 显示“当前范围 · N 家”。
- 点击摘要或向上拖动进入 half。
- half / expanded 展示 ViewportSet，使用当前发现页排序规则。
- 列表顶部可显示当前筛选摘要和清除筛选操作。
- N = 0 时显示“这个范围里还没有推荐地点”，并提供“查看全部地点”或“清除筛选”；“查看全部地点”应重新 fit FilteredSet，而不是跳到公开 POI 搜索。

### 10.4 已选 Pin 时

- card 展示选中地点。
- 向上展开后，选中地点在当前视野列表中保持高亮；列表整体仍按当前排序，不偷偷变成另一套数据。
- 如产品实现选择将选中项临时置顶，必须在视觉上注明“已选地点”，且 ID 集合和其余顺序仍可预测。
- 选中点被拖出视野后清除选中，回到 ViewportSet 普通列表。

### 10.5 抽屉与地图联动

- 抽屉实际高度通过 ResizeObserver 或等效方式反馈给地图安全边距。
- 展开抽屉不能重新初始化地图。
- 地图控件随抽屉上移，始终可点击。
- 抽屉覆盖区域不得继续响应地图拖动。
- 点击列表地点后，地图平移应在当前安全可视区完成，不能把 Pin 放在卡片正后方。
- 抽屉必须提供可点击的展开 / 收起按钮，不能只依赖拖拽手势。

## 11. 搜索、筛选与排序

- 搜索和筛选先作用于共同的 FilteredSet，再交给地图和列表。
- 地图不能另发一次请求并形成另一份结果。
- 当前地点、菜系、场景、人均、关键词和快速筛选行为继续沿用发现页已确认语义。
- “离我最近”在取得单次定位后生效；拒绝定位时保持原排序。
- 当前视野抽屉使用与完整列表相同的排序规则，但只显示 ViewportSet。
- 搜索高德地点建议只服务“按地点找”等现有筛选 / 记地点能力；它不能把建议结果临时当成 Foodprint 推荐 Pin。
- 清除筛选后恢复 BaseSet，并重新 fit 全部推荐地点。

## 12. 加载、空状态与异常状态

### 12.1 加载顺序

1. 服务端验证用户和当前小组。
2. 读取完整轻量地点索引。
3. 先渲染地图框架、标题、筛选和抽屉骨架。
4. 仅地图模式加载高德 SDK。
5. 地图 complete 后添加 Pin / 聚合并进入就绪状态。
6. 只有选中卡片和可见抽屉行需要的缩略图才按需签名 / 加载。

加载过程中不得先显示空列表再闪成地图；也不得用静态地图冒充加载完成。

### 12.2 地图致命错误

以下至少视为致命错误：

- JavaScript API Key 缺失或被域名白名单拒绝。
- JS 安全代理缺失、403、429 或持续 5xx。
- SDK 加载超时或 Promise 拒绝。
- 地图实例未在规定时间触发 complete。
- 地图容器 / WebGL 上下文出现无法恢复的错误。
- 功能开关明确关闭地图。

处理规则：

1. 立刻停止当前地图重试和地图初始化。
2. 销毁已创建的地图实例。
3. 保留已加载地点、搜索、筛选和排序。
4. 将当前会话切到列表。
5. 列表顶部显示：“地图暂时没打开，已为你切换到列表。”
6. 提供一次显式“重试地图”；不自动循环重试。
7. 记录匿名错误类别、阶段、耗时、版本和网络类型概况；不记录用户、组、地点名称、查询词或精确坐标。

地图错误不是数据错误。若地点授权读取本身失败，应走发现页数据错误状态，而不是展示一张没有数据的地图。

### 12.3 弱网与离线

- 弱网下地图超过超时门槛则切列表。
- 如果同一页面已成功拿到地点数据，列表应继续可用。
- 完全离线且没有当前数据时，使用 PWA 现有离线 / 重试语义，不显示虚假的旧地图。
- 地图失败后，同一次页面会话不再自动初始化；只有用户点“重试地图”或重新进入页面才尝试。

## 13. 功能开关与发布控制

- 增加服务端运行配置 DISCOVERY_DYNAMIC_MAP_ENABLED。
- 正常生产默认 true。
- false 时：
  - 发现页默认列表；
  - 不向浏览器下发 JS API Key；
  - 不加载高德 SDK；
  - 地图切换入口隐藏或显示为暂不可用，具体采用不误导用户的实现；
  - 不调用静态地图。
- 开关必须能通过腾讯云容器环境变量更新和应用重启生效，不需要修改代码或回滚数据库。
- 达到高德免费额度风险阈值、域名鉴权持续失败或地图错误率异常时，可以先关闭地图，再排查。

## 14. 性能与体验预算

以下是 V2.3 发布门槛，不替代真实基线记录：

- 同一次发现页生命周期只初始化一个高德地图实例。
- 仅列表模式不下载高德 JS SDK。
- 500 个地点以内的筛选与当前视野计算在目标手机上不造成可感知卡顿，单次纯计算目标不超过 50ms。
- 点击 Pin 后 100ms 内出现选中反馈，卡片骨架可先出现，缩略图随后加载。
- 真实中国大陆网络下，冷启动地图可交互 p75 目标不超过 5 秒；暖启动目标不超过 2.5 秒。
- 地图致命失败后，最迟 8 秒内出现可操作地点列表；已明确收到 401 / 403 / 429 / 5xx 时应立即切换，不等待满超时。
- 拖动期间不签名所有图片、不查询 POI、不反复调用服务端。
- 地图事件处理不得导致持续长任务、页面横向溢出或底部导航跳动。

若真实基线证明某阈值需要调整，必须在 PR 中展示设备、网络和前后数据，由产品负责人批准，不能由实现者静默放宽。

## 15. 可访问性与适配

- 支持 320、375、390、430px 宽度和常见手机安全区。
- 桌面仍使用当前窄屏应用容器时，保留同一交互语义，不另造一套桌面产品。
- 地图 / 列表切换、定位、重试、抽屉展开 / 收起和地点行均可通过键盘操作。
- 所有按钮触控面积不小于 44 × 44 CSS px。
- 抽屉状态变化提供 aria-expanded、可理解名称和合理焦点顺序。
- 地图不是获取地点信息的唯一方式；视野抽屉和完整列表提供文字等价内容。
- 选中态不能只依赖颜色；Pin 形状、尺寸或描边也要变化。
- 支持系统减少动态效果设置；抽屉和地图过渡应缩短或取消，但功能保留。
- 字号放大和长地点名不得遮住抽屉操作或详情按钮。

## 16. 隐私、安全、合规与配额

- 高德 JS API Key 在地图开启时必须送到浏览器，因此不是 Secret，但仍必须绑定 foodprint.com.cn 精确域名。V2.3 目标配置名为服务端运行时 `AMAP_JS_KEY`：Server Component 只在地图功能开启时把值传给地图客户端，不能继续由客户端直接读取构建期 `NEXT_PUBLIC_AMAP_KEY`；这样关图后可以真正停止下发。迁移期不得让两个变量长期并存成两份真相源。
- AMAP_SECURITY_KEY 只在腾讯云服务端代理内使用，不出现在 HTML、RSC、JS、日志或 Git。
- 安全代理只允许高德要求的受控路径、同源访问和必要方法，不接受任意上游 URL。
- Nginx / Next.js 日志不得记录带 jscode 的上游完整查询串。
- 地图代理必须有独立限流、超时和错误分类；限流值以真实 SDK 请求突发量校准，不能沿用普通 API 的低 burst 造成自我阻断。
- 只监控聚合的地图初始化、成功、失败类型、耗时和抽屉使用；不采集精确中心、边界、用户位置和私有地点信息。
- 上线前复核高德账户主体、用途、服务协议、控制台额度和是否存在付费扣费路径。
- 上线前必须让实际隐私政策与用户协议明确说明第三方地图服务提供方、使用目的、处理的数据类型、处理方式与范围，并提供高德隐私规则入口；涉及设备精确位置时，在用户主动操作后再请求系统权限，并完成适用的单独 / 明示同意流程。页面行为、政策文字与高德控制台主体必须一致。
- 若上述第三方服务告知、同意流程或实际运营主体授权尚未完成，DISCOVERY_DYNAMIC_MAP_ENABLED 必须保持 false；ICP 备案、域名可访问或接口技术可用都不能代替该门槛。
- 本项目不自动付费；接近免费额度时优先关闭动态地图并回到列表。

外部复核依据以发布当日版本为准：[高德开放平台服务协议](https://lbs.amap.com/pages/terms/)。本文件是产品与工程门槛，不替代针对实际运营主体的法律意见。

## 17. 事件与可观测性

最小事件集合：

- discovery_view_opened：map / list、是否因功能开关。
- amap_load_started。
- amap_ready：耗时档位、地点数量档位。
- amap_failed：阶段、匿名错误类别、HTTP 状态档位。
- discovery_fallback_to_list：原因类别。
- map_pin_selected：不带地点 ID。
- map_cluster_opened：数量档位。
- viewport_sheet_opened：half / expanded。
- viewport_sheet_place_opened。
- map_retry_clicked / map_retry_result。

禁止字段：

- user_id、group_id、place_id、地点名、查询词、经纬度、地图边界、完整 URL 查询串、签名图片 URL。

## 19. 高层验收

V2.3 只有同时满足以下条件才可关闭：

1. 默认动态地图、完整列表切换与自动降级符合本 Spec。
2. 地图、完整列表和视野抽屉通过 ID 集合一致性测试。
3. 小组权限、地点生命周期、退出登录和移除成员权限回归通过。
4. 拖动、缩放、聚合、Pin、卡片、抽屉、筛选和定位通过真实设备验收。
5. B「餐盘定位圆章」正式资产按 IC-08 规范接入，并通过真实高德底图、聚合数量与真机视觉验收。
6. 高德正式域名、安全代理、限流、超时、日志、隐私告知 / 同意和配额门禁通过。
7. 缺 Key、错域名、代理 403 / 429 / 5xx、SDK 超时、弱网、离线均能切列表。
8. 线上监控证明没有静态地图请求，也没有密钥或精确位置进入日志。
9. 自动化检查、干净 migration 重放、生产角色回归、性能记录和回滚演练归档。
10. 正式发布稳定观察期通过后，远端静态地图函数按交接单完成退役。

## 20. 后续迭代候选

以下内容只有在 V2.3 稳定并获得真实使用反馈后再讨论：

- 根据地图交互频率决定是否长期保持地图默认。
- 地点数量明显增长后的服务端空间索引或分块加载。
- 更丰富的 Pin 信息层级、地图主题或季节性视觉。
- 视野地点卡片的横向滑动模式。
- 多城市初始化与城市切换。
- 面向已推荐地点的路线组合或聚会规划。

后续若需要关闭地图默认，只修改功能开关或另立信息架构决定，不反向引入静态地图。
