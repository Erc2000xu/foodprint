# V1.3.2｜去试试：导航、附近搜索与完整转正流程

> 状态：开发完成，待 Preview 验收（2026-07-30）；整体视觉改版明确延期到 V3
> 前置版本：V1.3.1 已合并 main
> 核心目标：让“先记下一家店 → 找到并导航 → 真实体验 → 完整记一顿 → 进入发现”成为连续流程。

## 1. 当前问题

1. 候选卡没有直接导航入口，用户需要离开食迹重新搜索地点。
2. 卡片只显示城市和行政区，没有高德商圈。
3. 搜索不使用当前位置，同名门店较多时难以快速找到附近结果。
4. 点击“我去试过了→值得推荐”后，系统直接把地点放进发现，却没有填写推荐强度、“好在哪儿”、菜系、日期、照片、推荐菜和感受；用户还要去“记一顿”重新搜索。
5. 用户从“记一顿”直接记录一个已在“去试试”的地点后，候选记录不会同步退出待尝试列表。
6. 地点大类中的“小吃/街头餐饮”与菜系“小吃快餐/面食”重复，用户难以理解两者差异。

## 2. 产品判断

### 2.1 去试试不是收藏夹

它保存的是小组内“尚待验证的地点线索”。成熟地点的个人收藏仍是“下回吃”。因此候选卡应突出来源、期待、地点和出发动作，而不是复制发现卡的评分结构。

### 2.2 定位必须主动触发

页面提供明显的“按当前位置找”按钮。只有点击后才请求浏览器定位权限；坐标只发送给高德用于本次周边搜索与距离排序，不写入用户资料、不放入 URL、不长期保存。拒绝授权后仍能正常文字搜索。

### 2.3 地点唯一性以高德 POI 为准

候选、正式地点和记一顿使用同一个 `source_provider = amap + source_poi_id`。不得按店名字符串判断是否同一家，也不得让同一 POI 同时以待尝试和已推荐两种状态出现在同一小组。

## 3. 候选卡规格

### 3.1 信息

- 地点名称。
- 高德行政区：统一显示为 `北京市 · 朝阳区`。
- 高德商圈：有真实返回时显示，例如 `燕莎商圈`；没有时隐藏，不能猜测。
- 地址。
- 可选的“听说”和“想去理由”。
- 加入者和加入时间，保持低优先级。

### 3.2 操作

- 主操作：`导航去这里`。使用已保存的高德 POI、经纬度和地点名打开高德导航/路线页；明确这是第三方地图。
- 次操作：`我去过了`。
- 创建者操作：`编辑`，删除放入更多操作或编辑区，不与主操作争抢。

“导航去这里”应在卡片一级界面可见，不要求先进入详情页。按钮使用路线/箭头 SVG 图标加文字，不能只用图标。

## 4. 搜索与附近结果

1. 默认仍可直接输入餐厅、咖啡馆或酒吧名称。
2. 用户点击“按当前位置找”后调用现有浏览器定位能力。
3. 有坐标时，高德搜索改用周边检索并按距离排序；每项显示城市和距离。
4. 选择地点后继续填写来源和期待。
5. 定位失败、拒绝授权或高德暂不可用均提供明确状态，不阻断普通搜索。

## 5. 完整转正流程

### 路径 A：从去试试开始

1. 在候选卡点击“我去过了”。
2. 先确认真实体验。
3. 选择：
   - `值得推荐，记下这顿`
   - `这次先不推荐`
4. 选择值得推荐后，不立即进入发现；直接打开与“记一顿”相同的完整表单，地点已预选，用户无需再次搜索。
5. 完成地点大类、菜系、到访日期、推荐强度、好在哪儿、推荐菜/饮品、感受、照片和匿名选项。
6. 保存成功后，创建/更新正式地点、观点和本次到访；候选状态变为 `promoted`，从去试试列表消失并进入发现。
7. 保存失败时，候选仍保持 `pending`，用户填写内容不能被错误地标成已转正。

### 路径 B：从记一顿开始

1. 用户在“记一顿”搜索高德地点并完成完整表单。
2. 服务端按同一小组与高德 `source_poi_id` 查找待处理候选。
3. 若存在候选，在真实记录成功的同一业务事务中把候选改为 `promoted`。
4. 候选从去试试列表消失；保留后台审计记录，不物理删除历史。

### 暂不推荐

- 确认真实体验后可选择“这次先不推荐”。
- 候选状态变为 `dismissed`，从普通列表消失。
- 不创建公开负面评价，不进入发现和饭后聊。

## 6. 数据与事务要求

- 不能继续使用当前“先创建一个空的正式地点，再提醒稍后补充”的逻辑。
- 新增一个服务端完整转正入口，或扩展保存真实标记的数据库事务，使“保存标记/到访 + 更新候选状态”在业务上不可分割。
- 照片上传失败可以返回“记录已保存、部分照片待重试”的警告，但不能让候选继续显示为待尝试。
- 从记一顿保存时也必须执行候选同步，不能只在去试试入口处理。
- 旧 `promoted`、`dismissed` 候选保留用于审计；不做破坏性删除。

## 7. 分类调整

现有地点大类中的 `street_food = 小吃 / 街头餐饮` 与菜系 `quick_bite = 小吃快餐 / 面食` 发生层级混淆。

本迭代采用兼容式调整：

1. 新表单不再提供“小吃/街头餐饮”作为地点大类；吃饭类统一选择“餐厅”。
2. “小吃快餐/面食”继续作为菜系/餐饮类型存在。
3. 历史 `street_food` 数据不直接删除；先统一显示和筛选为“餐厅”，再通过前向 migration 改为 `restaurant`。
4. 迁移前后均需保证旧地点可以被搜索、筛选和显示。
5. 咖啡馆、茶饮/饮品、酒吧、烘焙/甜品继续作为大类保留。

## 8. 高德商圈

- 候选使用与发现页相同的高德逆地理编码缓存。
- 新候选保存时尝试写入商圈缓存；历史候选通过 V1.3.1 定义的后台队列补齐。
- 页面不直接调用高德并把结果当作永久真值；统一由服务端受节流地刷新。
- 商圈暂未补齐时只隐藏商圈标签，不影响行政区、导航和转正。

## 9. 视觉方向稿需要回答的问题

1. 导航按钮如何成为明显主操作，但不压过“我去过了”的产品主流程。
2. 来源/期待是否保留纸条感或手账感，同时保持卡片紧凑。
3. 商圈、行政区和地址如何形成清晰层级。
4. 搜索与当前位置入口如何让用户一眼理解。
5. 腊肠犬只用于空状态或轻提示，不进入每张候选卡。

### 9.1 已确认的版本边界（2026-07-29）

- 三套方向稿仅作为未来 V3 视觉系统的底稿，不属于 V1.3.2 的整体页面改版范围。
- 产品负责人在三套方向中更偏向 **B“出发地图”**。V3 应优先研究其轻路线、附近搜索与出发感，但不得照搬大块装饰地图造成列表过长。
- V1.3.2 聚焦本文件第 3–8 节的功能、数据一致性和必要的局部 UI 调整：导航、商圈、附近搜索、完整转正、候选同步和分类兼容。
- V1.3.2 新增按钮和状态仍必须遵守视觉资产台账，使用成熟的项目内 SVG；不以“延期到 V3”为理由继续使用 emoji。

## 10. 验收标准

- 候选卡一级界面可一键打开高德导航。
- 使用真实高德商圈；无商圈数据时不伪造、不留空标签。
- 定位需要用户主动触发，授权后同名地点按距离展示。
- “值得推荐”必须完成一顿表单后才进入发现。
- 从“记一顿”直接保存相同 POI 后，去试试候选自动退出待处理列表。
- 历史 `street_food` 地点在分类调整过程中不丢失、不报错，最终统一为“餐厅”。
- 所有新增图标均先登记在视觉资产台账，不出现临时 emoji。
