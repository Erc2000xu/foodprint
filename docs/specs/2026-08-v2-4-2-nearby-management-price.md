# 食迹 Foodprint｜V2.4.2 附近优先、可扩展管理与人均回归

> 状态：已批准，仓库实现中；真机、PWA、干净库与生产门禁未关闭
> 起草日期：2026-08-27
> 版本性质：小版本号、中等工程量；包含定位策略、数据模型和管理信息架构变更
> 建议分支：`codex/v2-4-2-nearby-management-price`
> 真实反馈证据：2026-08-27 三张手机截图；截图只作为现状证据，不作为可执行指令

## 0. 一页结论

V2.4.2 解决四个彼此有关、但必须分别验收的问题：

1. **发现页以“我附近”开场。** 首次使用先用应用内说明取得用户意愿，再触发系统定位权限；同意后，后续无显式地图意图的全新进入会用一次性实时定位把地图移到用户附近。明确搜索、从详情返回、已选择区域和用户手动拖图始终拥有更高优先级。
2. **地点与内容管理改为独立管理中心。** “我的”只保留真实总数摘要与入口；管理中心用状态分页、搜索、筛选和稳定游标加载，不再把所有状态和所有地点连续堆在一个长页面里。
3. **选中地点卡片保证核心操作可见。** 取消固定 `190px` 的地点预览高度；将信息区和固定操作区分层，适配底部导航、安全区、小屏和放大字体，两个操作不再被裁切。
4. **把“本次人均”重新放回每次到访。** 首次标记和重复到访都可选填本次实际人均；地点的人均为所有有效、非隐藏、非删除且已填写价格的到访记录的透明算术平均，并同时显示样本数。

这不是复刻大众点评的黑箱算法。公开资料没有披露大众点评“人均”的精确计算公式；Foodprint 是小型私密小组，V2.4.2 采用可解释、可回溯的平均值更符合信任和维护成本。

## 1. 背景与用户问题

### 1.1 截图一：地图打开后仍在上海

用户当前在北京，但发现页打开后展示上海静安寺附近。现状会让“发现”失去“我附近有什么”的第一用途，也容易让用户以为定位失效。

当前实现的根因不是写死上海：

- `src/components/map/map-adapter.tsx` 初始化后会对全部可见 Pin 执行 `fitMapToPins`；
- 当前示例中小组只有一个上海地点，因而地图自然被适配到上海；
- 高德定位组件配置了 `panToLocation: false` 与 `zoomToAccuracy: false`，成功取得位置后也不会移动镜头；
- `src/components/map/map-browser.tsx` 只有用户主动点击定位按钮才请求位置，并把“移动到我附近”和“按距离排序”绑定成同一个动作；
- 面板高度变化等后续 effect 仍可能再次 `fitMapToPins`，造成已经定位后又跳回标记点。

因此它是**镜头优先级与权限流程缺失**，不是把默认中心坐标从上海改成北京就能解决的 Bug。

### 1.2 截图二：管理区无法扩展到数百地点

“我的 → 地点与内容管理”把上架、下架、候选和隐藏内容分段后全部纵向渲染。地点一多，查找、判断状态和执行管理都会变慢。

当前实现还有两个数据正确性问题：

- `src/app/admin/page.tsx` 对部分管理 RPC 使用 `p_limit: 10`；
- 页面卡片显示的是本次加载数组的 `.length`，不是数据库中的真实总数。

因此截图中的 “10 个上架中地点” 可能只是“最多取了 10 条”，而非完整统计。现有 `list_group_place_management` 虽有游标参数，但只按 `updated_at` 排序；时间相同的记录存在翻页遗漏或重复风险。其他列表则没有游标。

按钮“查看 / 管理记录”因容器宽度、换行和每行标题长度不同而产生不一致，也没有形成统一的可点击尾部区域。

### 1.3 截图三：选中地点后按钮被底部导航切掉

`src/app/globals.css` 把地点预览态固定为 `height: 190px`。当前卡片同时包含拖拽柄、标题、图片、简介和双按钮，实际内容高度超过容器；按钮虽在 DOM 中，却落在底部导航之后或滚动区不可达的位置。

这是核心操作的可用性缺陷，不应只通过再缩小字号、图片或按钮来掩盖。

### 1.4 人均在新到访模型中断链

旧模型 `place_marks.price_per_person` 与 `visits.price_per_person` 曾支持人均；V1.3 新增的耐久到访模型 `visit_records` 没有价格字段，相关 RPC、Server Action 与两个“记一顿”表单也未传价格。首次标记的兼容包装器还会明确向旧价格参数传 `null`。

发现页类型和卡片仍保留 `pricePerPerson`，但当前读模型更接近“取最新内容中的某个人均”，不是所有到访记录的平均值。于是出现“界面似乎支持、写入链路已经消失、汇总语义不正确”的断层。

## 2. 目标、成功判断与优先级

### 2.1 版本目标

| 优先级 | 目标 | 用户结果 |
| --- | --- | --- |
| P0 | 恢复每次到访的人均写入并保证聚合正确 | 新数据不再丢失，历史可确定数据可回填 |
| P0 | 修复地点预览操作被遮挡 | 任何支持的手机尺寸都能看见并点击主要操作 |
| P1 | 无显式地图意图时优先显示当前位置附近 | 用户在北京打开时不再默认被带到上海 |
| P1 | 管理页面支持数百至数千条记录 | 真实计数、快速查找、稳定翻页、权限不扩大 |

### 2.2 可度量成功标准

- 已同意“打开时定位”的用户，在定位成功后的地图中心距本次定位点不超过 500 米，默认缩放级别在 13–15 之间。
- 一次全新进入最多发起一次定位请求；拒绝后不循环弹系统权限框。
- 原始经纬度不进入 URL、数据库、`localStorage`、`sessionStorage`、日志或指标。
- 320×568、375×667、390×844、430×932 四类视口下，地点预览的主要操作完整可见、可聚焦、可点击，并位于底部导航与安全区之上。
- 管理中心在 500 条上架地点、200 条下架地点、100 条候选及 200 条隐藏内容的测试数据下，首屏只读取当前状态的 20 条；稳定翻页无遗漏、无重复。
- 管理摘要显示数据库真实总数，不再受 `p_limit` 影响。
- 任一地点的人均在地图、列表与详情中一致；示例 `¥80、¥120、空值、已隐藏 ¥999` 的结果必须是 `人均约 ¥100 · 2 次记录`。

### 2.3 非目标

- 不实现大众点评式商业排序、反作弊信誉分、折扣校正或机器学习价格模型。
- 不自动读取用户持续轨迹，不使用后台定位，不上传当前位置。
- 不在本版本重做整个“我的”页面、全站视觉系统或 V3 时间线视觉。
- 不新增批量下架、批量删除、CSV 导入或复杂桌面数据表。
- 不修改已发布 migration；只新增向前兼容 migration。
- 不把仍未关闭的 V2.4.1 照片 P0 混入本版本，也不以 V2.4.2 的完成替代其真机与生产验收。

| 对象 | 可验证做法 | Foodprint 采用 | 不采用／原因 |
| --- | --- | --- | --- |
| 大众点评 | 官方帮助说明评分以平均值为基础，还考虑评价数量、时间及贡献等级；不足 4 条评价时不计算商户评分 | 只借鉴“有效真实记录、样本数和内容状态会影响汇总”的原则 | 官方没有公开“人均”精确公式；不声称复刻、不引入无法解释的黑箱 |
| 美团商户排名规则 | 排名使用真实用户数据和多因素，并有异常数据治理 | 隐藏/删除的到访不进入聚合；保留未来异常治理空间 | 小型私密小组暂无必要做复杂信誉权重和商户排名 |
| 主流地图／本地生活应用 | 打开地图优先提供当前位置、明显定位按钮；用户主动搜索或移动后尊重当前意图 | 首次解释后一次定位，后续按设备偏好自动定位；镜头采用明确优先级 | 不持续追踪，不因定位失败阻断发现页 |

### 3.1 人均算法决策

V2.4.2 使用：

```text
地点人均 = round(
  所有有效 visit_records.price_per_person 的算术平均值
)

有效 = price_per_person 非空
    且 deleted_at 为空
    且 hidden_at 为空
    且到访属于当前 group_place
```

显示规则：

- `N = 0`：`人均待补充`；
- `N >= 1`：地图／列表卡片显示 `人均约 ¥X`；
- 详情摘要显示 `人均约 ¥X · 基于 N 次到访记录`；
- 到访时间线的单条记录可显示 `这次人均 ¥Y`。

本版不设 4 条起显门槛，因为 Foodprint 是人数较少的私密小组；用“约”和样本数诚实表达不确定性。未来若真实数据表明异常值影响明显，再单独立项中位数、截尾均值或信誉权重，不能静默改变历史口径。

## 4. 产品方案 A：发现页附近优先

### 4.1 “地图中心”和“列表排序”解耦

定位按钮只负责：

1. 请求一次当前位置；
2. 显示用户位置标记；
3. 把地图镜头移到附近；
4. 更新“当前范围 · N 家”。

它**不再隐式把完整列表切为按距离排序**。若需要“离我最近”，应保留为明确的排序选择，避免用户只想回到当前位置却发现列表顺序被改变。

### 4.2 新用户权限流程

第一次在该设备、该登录状态下全新进入发现页，若没有更高优先级的地图意图，显示非阻塞式说明卡：

> **先看看你附近**
>
> 使用当前位置，把地图移到你身边。坐标只用于这次地图，不保存。

操作：

- 主按钮：`使用当前位置`
- 次按钮：`暂不`

只有点击主按钮后才调用系统定位。选择“暂不”仍可正常使用地图、列表、搜索和筛选。不得用全屏强制弹窗阻断页面。

同意后仅保存设备级布尔偏好，例如 `location-on-entry: true`，不保存坐标。退出登录时清理该偏好，避免共用设备上的下一个账户继承。建议在“我的 → 隐私与位置”提供 `打开发现时自动定位` 开关；关闭后立即清理偏好和内存位置。

### 4.3 后续进入行为

若用户曾明确同意，且当前进入没有显式地图意图，则每次**新的发现页会话**最多请求一次实时位置。权限仍由浏览器决定；若浏览器要求再次手势，不尝试绕过，改为显示定位按钮提示。

“新的发现页会话”定义：不是详情返回、不是同一页筛选刷新、不是 PWA 恢复到仍存活的地图实例。开发时必须用单次状态机或 request id 防止 React effect 重复触发。

### 4.4 镜头优先级（从高到低）

```text
用户当前手动拖动／缩放
  > 用户主动点击定位按钮
  > 明确搜索结果、地区筛选或选中地点
  > 从地点详情返回时的有效地图状态
  > 已同意的“打开时定位”一次性当前位置
  > 当前小组全部 Pin 的适配范围
  > 无 Pin 时由地图 Provider 提供的城市级降级视野
```

规则：

- 一旦用户开始拖图，异步返回的旧定位结果不得把镜头抢回去；
- 选中上海地区或上海地点时，即使用户人在北京，也应展示上海；
- 从详情返回时恢复用户离开前的意图，不再重新定位；
- 面板高度变化只调整 padding，不重新 `fitMapToPins`；
- 只有用户点击“查看全部地点”才适配全部 Pin。

### 4.5 定位参数与坐标处理

使用现有高德 JS API 2.0 的一次性 `AMap.Geolocation.getCurrentPosition`：

- `enableHighAccuracy: true`
- `timeout: 10_000`
- `maximumAge: 60_000`
- `convert: true`，保持与高德 Pin 一致的 GCJ-02
- `showButton: false`
- `panToLocation: false`
- `zoomToAccuracy: false`

镜头由应用在确认 request id 仍有效后执行 `setZoomAndCenter(14, location)`，从而避免 Provider 自动镜头和 React 状态互相争抢。不得使用 `watchPosition`。

### 4.6 状态与失败文案

| 情况 | 页面行为 | 文案 |
| --- | --- | --- |
| 定位中 | 地图继续可用，定位按钮显示进行态 | `正在找你的位置…` |
| 成功且附近有地点 | 居中、显示用户 Pin、刷新当前范围 | `已回到你附近` |
| 成功但附近为 0 | 保持当前位置，不跳去外地 Pin | `你附近还没有朋友标记的地点` + `查看全部地点` |
| 用户拒绝 | 不循环弹权限；保持当前地图 | `没有使用位置，仍可浏览全部地点` |
| 超时／不可用 | 保持当前地图，可重试 | `暂时无法取得位置，请稍后再试` |
| 系统永久阻止 | 给出浏览器设置提示，不伪造成功 | `请在浏览器设置中允许 foodprint.com.cn 使用位置` |

不得把“定位失败”和“附近没有地点”混为同一个空状态。

### 4.7 隐私边界

- 原始经纬度只保留在当前地图组件内存中；
- 不写数据库、URL、Cookie、`localStorage`、`sessionStorage`、错误日志或分析事件；
- 现有地图返回状态若可能间接保存定位得出的精确中心，必须改为内存/history state，或在保存前省略/降精度；不得原样序列化精确定位点；
- 指标只记录 `accepted / declined / granted / denied / timeout / unavailable`、耗时区间和是否出现附近结果，不记录坐标、地址或精确距离；
- 权限用途文案、隐私说明和高德 SDK 合规披露需在生产发布前复核。

### 4.8 工程改动指引

重点文件：

- `src/components/map/map-browser.tsx`：定位状态机、进入策略、排序解耦、失败态；
- `src/components/map/map-adapter.tsx`：镜头命令优先级、取消初始化和 padding 变化的无条件 fit；
- 新增轻量定位偏好与说明组件；
- 地图返回状态模块：避免持久化精确定位中心；
- 对地图 Adapter 使用 fake AMap/注入定位结果做确定性测试。

## 5. 产品方案 B：可扩展的地点与内容管理中心

### 5.1 信息架构

“我的”页不再直接渲染所有管理记录，只显示：

- 标题：`地点与内容管理`
- 2×2 摘要：`上架中`、`已下架`、`去试试候选`、`已隐藏内容`
- 真实总数
- 主入口：`打开管理中心`

新建独立的 Owner/Admin 路由，建议 `/admin/content`。顶部保留四个状态标签：

1. 上架中
2. 已下架
3. 去试试候选
4. 已隐藏内容

默认进入“上架中”。一次只请求和渲染当前标签的数据。

### 5.2 当前标签的结构

```text
标题 + 返回
状态标签（可横向滚动，显示真实数量）
搜索框：地点名 / 地址
可选筛选：最近更新 / 名称；候选可筛“已移除”
当前显示 1–20 / 共 N 条
紧凑管理行 × 20
加载更多
```

手机端使用紧凑列表行而非桌面宽表格。每行包含：

- 地点或内容标题，最多两行；
- 地址或作者/时间等次要信息，最多两行；
- 观点数、到访数、照片数等当前已有摘要；
- 状态和最后更新时间；
- 统一尾部操作 `管理 ›`，或整行点击进入管理详情。

操作区必须：

- 最小触控高度 44px；
- `white-space: nowrap`；
- 统一最小宽度和内边距；
- 不因标题长短改变按钮尺寸；
- 不再使用会断成两三行的“查看 / 管理记录”。

### 5.3 搜索、分页与空状态

- 搜索由服务端完成，支持地点名和地址的大小写/空格容错；300ms 防抖或显式搜索均可，但不得每个按键并发无界请求；
- 每页默认 20，服务端最大 50；
- 使用稳定 keyset cursor `(sort_at, id)`，排序条件和游标必须完全一致；
- 返回 `items`、`next_cursor`、`has_more`、`total_count`；
- 搜索或筛选改变时清空旧游标和旧结果；
- 空状态区分“此状态没有数据”和“没有搜索结果”；
- 失败时保留已加载行并提供 `重试`，不把失败显示成 0 条。

### 5.4 数据接口

新增版本化管理 RPC，不修改已上线签名：

- `get_group_content_management_counts_v2_4_2()`：一次返回四类真实总数；
- `list_group_place_management_v2_4_2(...)`：上架/下架地点；
- `list_group_candidate_management_v2_4_2(...)`：候选；
- `list_group_hidden_content_v2_4_2(...)`：隐藏内容。

参数至少包含：

- `p_status`
- `p_query`
- `p_limit`
- `p_cursor_sort_at`
- `p_cursor_id`

返回只包含当前管理界面所需字段，不取完整照片原图或正文。索引应由 `EXPLAIN ANALYZE` 和代表性种子数据验证；至少覆盖 `group_id + status + sort_at + id`，文本搜索根据当前 PostgreSQL 能力选择规范化字段或 `pg_trgm`，不得无评估引入扩展。

### 5.5 权限与审计

- 入口、页面、RPC 均只允许当前小组 Owner/Admin；Member 不能依靠直输 URL 或 RPC 调用绕过；
- 原有下架、恢复、隐藏、恢复的权限和审计日志不变；
- 列表重构不允许把作者原始观点改写成管理员内容；
- 计数同样受当前 group 和 RLS/函数权限约束，不能泄露其他小组数据；
- 在权限变化或会话过期时，页面进入明确的无权限/重新登录状态。

### 5.6 工程改动指引

重点文件：

- `src/components/admin/place-content-management.tsx`：缩成摘要/入口或拆分；
- `src/app/admin/page.tsx`：改为读取真实计数，不再拿 10 条列表冒充统计；

## 6. 产品方案 C：地点预览 Bottom Sheet

### 6.1 布局结构

地点选中态改为三段：

```text
拖拽柄 + “已选地点 / 收起”       固定
地点图片、名称、简介、推荐信息     可滚动
主要操作 + 次要操作                固定，始终在导航上方
```

删除 `.viewport-sheet--place_preview { height: 190px; }` 这一不可满足内容需求的约束。建议使用内容感知高度：

```css
height: clamp(260px, 34dvh, 320px);
max-height: calc(100dvh - 顶部安全空间 - 底部导航占位);
```

具体数值由现有导航高度变量和真机结果确定，不能再复制魔法数字。容器用 `display: flex; flex-direction: column;`；中间内容 `min-height: 0; overflow-y: auto;`；操作区 `flex: none` 并包含底部安全区。

### 6.2 操作规则

- 主操作沿用当前真实业务动作，视觉优先级最高；
- 次操作只在确有目标时出现；若数量为 0，隐藏或把主操作扩为全宽，不显示无效按钮；
- 所有按钮/链接最小高度 44px；
- 长地点名最多两行，不能把操作区向下挤出；
- 放大到 200% 字体时允许内容滚动，但操作仍可达；
- 拖动面板、滚动内容和拖动地图三类手势不得互相劫持。

### 6.3 验收方式

除视觉截图外，自动化断言两个操作元素的 `getBoundingClientRect()`：

- bottom 小于等于底部导航 top；
- top/bottom 在视口内；
- 非 `display:none`、非被 overlay 拦截；
- 可通过触摸、键盘 Tab 和 Enter 触发真实路由/动作。

## 7. 产品方案 D：“本次人均”写入与地点平均

### 7.1 表单

在两条路径加入相同字段：

1. 首次标记一个新地点；
2. 已有地点的“再次到访 / 记一顿”。

字段：

- 标签：`本次人均（可选）`
- 前缀：`¥`
- 帮助文案：`按这顿最终实付金额 ÷ 就餐人数填写；不确定可留空。`
- 移动键盘：`inputMode="decimal"`
- 允许：`1–99999`，最多两位小数；空值合法
- 拒绝：0、负数、非数字、无穷大、超过范围和多于两位小数

Server Action 必须重复校验，不能只依赖浏览器输入属性。不得在日志或分析事件中记录具体金额。

### 7.2 权威数据源

`visit_records.price_per_person numeric(10,2) null` 是 V2.4.2 起唯一用于地点平均的权威字段。首次标记也必须创建一条且只创建一条带价格的 `visit_record`，不能同时把 `place_marks` 和 `visit_records` 当两次样本。

旧字段只用于可确定的迁移和旧客户端兼容：

- 可通过 `visit_records.legacy_visit_id = visits.id` 一一对应时，把 `visits.price_per_person` 回填到空值；
- 只有能证明某个旧 `place_mark` 与唯一到访一一对应时才可回填；
- 不确定的数据保持 `null`，不得猜测；
- migration 必须幂等、可在干净数据库完整重放，并输出脱敏数量验证查询。

### 7.3 写入接口

使用版本化 RPC，推荐：

- `record_place_visit_v2_4_2(..., p_price_per_person numeric)`
- `save_candidate_promotion_mark_v2_4_2(..., p_price_per_person numeric)`

若技术预检证明现有函数可安全新增默认参数，也仍需避免破坏旧客户端的 PostgREST 签名解析。默认选择新函数名，旧 RPC 保留到回滚观察完成。

一次提交内保证：业务记录、到访记录和价格写入的原子性与现有幂等语义。照片仍按 V2.4.1 已批准链路处理，不在本版改写照片事务边界。

### 7.4 聚合读模型

新增共用 SQL 聚合/视图或内联到版本化读 RPC，确保发现列表、地图 Pin 卡片与地点详情使用同一口径：

- `avg_price_per_person`
- `price_sample_count`

发现读模型建议版本化为 `list_discovery_index_v2_4_2`；地点详情读模型同步返回这两个字段。若保持返回形状兼容，可在技术预检后选择替换内部实现，但必须有 SQL 合同测试防止以后重新变成“最新一条价格”。

删除/隐藏一条到访后，下一次读取必须排除其价格；恢复后重新纳入。地点下架只影响地点可见性，不应物理删除价格历史；恢复地点后汇总保持一致。

### 7.5 展示

| 位置 | 有样本 | 无样本 |
| --- | --- | --- |
| 地图地点卡片 | `人均约 ¥126` | 可省略或 `人均待补充`，按现有信息密度选择一致规则 |
| 发现列表 | `人均约 ¥126` | `人均待补充` |
| 地点详情摘要 | `人均约 ¥126 · 基于 5 次到访记录` | `还没有人均记录` |
| 单次到访时间线 | `这次人均 ¥138` | 不显示价格行 |

金额显示使用人民币符号与中文格式；地点平均四舍五入为整数，单次记录最多显示两位小数且去除无意义的 `.00`。

### 7.6 导出与用户权利

现有数据导出若包含到访记录，应加入 `price_per_person`；删除、隐藏和恢复行为延续当前权限模型。不得把具体金额暴露给小组之外或公共缓存。

## 8. 数据、接口与发布架构

### 8.1 建议 migration

新增单一版本 migration，例如：

`supabase/migrations/20260827090000_v2_4_2_nearby_management_price.sql`

至少包含：

1. `visit_records.price_per_person numeric(10,2)` 与约束；
2. 确定性旧数据回填；
3. 人均聚合所需索引/读模型；
4. 版本化写入 RPC；
5. 管理真实计数与稳定分页 RPC；
6. 必要 grant/revoke 与 `search_path` 固定；
7. SQL 注释，说明平均值口径和游标合同。

若单文件过大，Codex 可按“价格模型”和“管理读模型”拆成连续两条 migration，但发布顺序和回滚说明必须清楚；不得把它们写回已发布 migration。

### 8.2 类型合同

TypeScript 读模型新增：

```ts
type PriceSummary = {
  avgPricePerPerson: number | null;
  priceSampleCount: number;
};
```

金额从 PostgreSQL 返回时可能是字符串；必须在边界层解析、验证和规范化，不能在各组件中各自 `Number(...)`。

### 8.3 功能开关与回滚

- 新增 `DISCOVERY_LOCATION_ON_ENTRY_ENABLED` 作为服务器控制的定位入口 kill switch；关闭后保留手动定位；
- 数据库先部署，应用后部署；新增字段和新 RPC 对旧客户端无破坏；
- 应用回滚时旧 RPC 仍存在，新增价格列保留，不做破坏性 down migration；
- 管理中心故障时，“我的”可退回现有管理入口，但真实计数不得继续冒充 10 条上限；
- PWA 必须通过版本更新验证，避免旧 bundle 与新 RPC 长时间错配；
- 任何发布、数据库和生产变更遵循 `docs/RELEASE_SOP.md`，由项目负责人手动批准。

### 8.4 可观测性

允许的匿名结果事件：

- 定位说明展示/接受/暂不；
- 定位结果枚举与耗时桶；
- 地点预览主要操作是否成功触发；
- 管理列表加载成功/失败、页大小和耗时；
- 人均字段是否填写（仅布尔值），写入/聚合错误码。

禁止记录：原始经纬度、地址、具体人均金额、搜索原文、用户内容、照片路径或鉴权信息。

## 12. 风险、取舍与未决批准项

### 12.1 已推荐取舍

- 推荐“首次应用内说明 + 同意后后续自动定位”，而不是第一次打开就无说明触发系统权限。
- 推荐透明算术平均 + 样本数，而不是声称复刻大众点评。
- 推荐独立管理中心 + 服务端稳定游标，而不是在“我的”里做无限长虚拟列表。
- 推荐固定操作区的 Bottom Sheet，而不是继续缩短内容适配 190px。

### 12.2 需项目负责人批准

批准本 Spec 即同时确认以下产品决定：

1. V2.4.2 的定位策略取代 V2.3 中“初次进入绝不主动出现定位引导”的旧约束；仍保留用户先选择、可拒绝、不阻断和不保存坐标。
2. 地点人均采用所有有效已填到访的透明算术平均，1 条也可显示，但必须带“约”和样本数。
3. 地点管理从“我的”长页面迁到独立 `/admin/content` 管理中心。
4. V2.4.2 与尚未关闭的 V2.4.1 照片 P0 按默认单分支规则串行，不互相冒充完成。

### 12.3 技术预检必须回答

- 现有 map return state 是否会持久化由定位产生的精确中心，如何在不破坏详情返回的前提下消除；
- 当前 RPC/生成类型的版本化命名和 Supabase 免费版迁移成本；
- 旧 `place_marks` 与 `visits` 能确定回填多少条，不能确定的数量；
- 管理文本搜索是否需要 `pg_trgm`，还是规范化 `ILIKE` + 合适数据量已足够；
- V2.4.1 当前分支、PWA 版本与照片工作是否会和本版本触碰同一文件。
