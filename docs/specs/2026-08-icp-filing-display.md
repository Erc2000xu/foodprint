## 1. 规则结论

当前公开要求的核心不是把“ICP”三个字随意放在某个页面，而是把**与该网站对应的准确网站备案号**放在网站首页底部中央，并使备案号能够链接到工信部 ICP/IP 地址/域名信息备案管理系统：

- 工信部《非经营性互联网信息服务备案管理办法》第十三条要求，网站开通时在主页底部中央位置标明备案编号，并在备案编号下方按要求链接备案管理系统，供公众查询核对。
- 工信部公告已将备案管理系统正式域名调整为 `https://beian.miit.gov.cn/`；不使用历史上的 `miitbeian.gov.cn`、`miibeian.gov.cn` 等旧域名。
- 腾讯云 2026 年备案后处理说明要求，备案成功的主域名和 `www` 域名都应可访问并在网站底部展示备案号和工信部链接。
- 按当前腾讯云说明，非广东备案通常展示**网站/服务备案号**（例如 `京ICP备12345678号-1`），不能用不带网站序号的主体备案号代替；广东规则存在差异。腾讯云服务器的北京地域不等于备案地，最终以工信部/腾讯云备案记录为准。

## 2. 本项目拟采用的位置

备案信息不放在登录框、管理页、导航栏或某一个业务页面内，而是放到根布局 `src/app/layout.tsx` 的全站页尾：

1. 所有页面内容之后；
2. 页面底部中央对齐；
3. 备案号作为第一行可点击文本，链接到 `https://beian.miit.gov.cn/`；
4. 下方增加“工信部备案查询”辅助链接，仍指向同一官方地址；
5. 手机和桌面端均显示，视觉上使用低强调度，不干扰登录、地图和记录操作。

这样首页、登录页、已登录页面和 `www` 跳转后的正式页面都使用同一个实现，避免只在某个页面悬挂而被核查遗漏。当前组件通过 `NEXT_PUBLIC_ICP_RECORD` 选择性启用；变量为空时完全不渲染，因此在负责人确认前不会向线上显示占位号。

## 5. 已执行的发布步骤

1. 将准确备案号写入受控生产配置 `NEXT_PUBLIC_ICP_RECORD`，不写入 Git 中的生产配置。
2. 用该公开构建参数重新构建生产镜像；不需要修改 Supabase、DNS、证书或数据库。
3. 先在 `127.0.0.1:3001` 临时容器验证：页尾出现准确文字，两个链接均为 `https://beian.miit.gov.cn/`，无占位文本。
4. 切换生产容器并检查 `/api/health`、首页、登录页和 HTTPS 证书。
5. 从 `foodprint.com.cn` 和 `www.foodprint.com.cn` 分别检查页尾；`www` 仍应先 308 到裸域，再展示同一备案信息。
6. 若以后备案号、网站主体、域名或备案地发生变化，必须重新核对并重新构建，不能只改浏览器缓存或 Nginx 文本。

## 6. 后续合规项

腾讯云当前说明还提示：ICP备案完成后，网站通常还需要在规定期限内办理公安联网备案，并按公安平台生成的要求将公网安备编号/图标放在页尾；部分省份还可能要求版权所有信息。该项不使用猜测编号，待负责人提供官方生成的信息后另立小任务接入。

## 7. 2026-08-16 V2.4 永久门禁修订

实际生产检查发现：`NEXT_PUBLIC_ICP_RECORD` 为空时组件返回 `null`，而发布流程没有把该公开值列为必填，因此仍可能成功发布一个没有备案页尾的镜像。第 2–5 节记录的是 2026-08-06 当时的实现与上线历史；从 V2.4 起，以下合同覆盖其中“空值可以合法不显示”的旧行为：

1. 已确认备案号 `京ICP备2026047829号-1` 不再是可选视觉配置；根布局必须无条件渲染统一备案组件。
2. 若保留环境变量，只允许作为经过格式与准确值校验的显式覆盖；缺失或不匹配必须让生产构建 / 发布失败，不能返回 `null` 后继续上线。
3. 全局路由、地图 / 列表模式、登录状态、运行开关和页面重构均不得决定备案组件是否存在。
4. 固定底部导航必须为页尾保留真实间距；320 / 390 / 430px、桌面和 PWA standalone 下滚到页面底部时不得遮挡。
5. 组件测试、根布局测试、生产构建产物检查和正式域名冒烟必须同时验证准确文字与 `https://beian.miit.gov.cn/` 链接。
6. 删除、条件隐藏或移动备案组件必须同时修改专门合规测试和 V2.4 交接；测试不通过时禁止发布。
