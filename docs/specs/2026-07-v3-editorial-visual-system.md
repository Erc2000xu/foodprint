# V3｜视觉系统与精致表达

> 状态：待立项
> 前置依赖：V2 稳定运行，已有真实用户反馈与可用的核心数据结构
> 目标：不改变已验证的产品逻辑，以更成熟的移动端视觉系统把“记录、分享、相聚”的温度表达出来。

## 1. 设计方向

食迹应避免两种极端：一边是工具后台般的冷硬表单感，另一边是堆砌文艺词汇和装饰的阅读负担。视觉要像日常生活中被认真留住的一顿饭：清爽、克制、可信，有一点手写和手作感，但始终易读、易操作。

## 2. 包含范围

- 统一设计 token：颜色、字号、字重、行高、圆角、阴影、间距、动效和状态色。
- 定制三级小碗图标：一、二、三层轮廓在小尺寸下仍一眼可辨，兼顾空/选中/汇总状态。
- 发现、去试试、记一顿、饭后聊、我的和地点详情的导航、按钮、卡片与空状态统一。
- 地点详情时间线探索纸张、便签、牛皮纸、轻微毛边或撕页般的手作质感；内容仍是文本和真实图片，非不可访问的整块图片。
- 用户感受区的统一书写性排版，例如一种可控的衬线/书写感辅助字体、引语块、颜色和字重层级。
- 发现卡的轻量照片轮播：每次最多 2 至 3 张真实图片，支持手势、暂停和首帧稳定。

## 3. 不包含范围

- 改写 V1.2/V1.3 的地点状态、推荐计算、权限和社交边界。
- 评论、点赞、回复或任何会增加内容治理负担的互动。
- 为每位用户随机切换字体、低对比度文字、自动播放长动效或影响加载的装饰图。

## 4. 分阶段执行

1. 研究：收集小范围用户反馈，梳理阅读、操作和辨识困难；建立现有页面截图基线。
2. 基础系统：确定设计 token、字体授权/加载策略、小碗图标规范、组件状态和无障碍规则。
3. 关键页面：优先地点详情、记一顿、发现卡；再覆盖去试试和饭后聊。
4. 质感层：实现可复用 CSS/SVG 纸张边缘、纹理和微动效，确保可关闭/降级。
5. 质量验证：真机、低端机、慢网、深浅环境、不同字体渲染、辅助技术和视觉回归。

## 5. 设计与工程约束

- 所有交互图标有文字或无障碍标签，不能只依赖颜色、形状或动效传达关键信息。
- 正文、日期、地址、按钮在移动端保持可读对比度和触摸尺寸；用户内容不因装饰性字体而难读。
- 手作边缘应使用轻量 SVG/CSS 或可缓存资源，避免为卡片生成大图片；尊重减少动态效果偏好。
- 照片轮播只使用已授权的小组私有照片，采用签名 URL 缓存策略且不泄露原始对象路径。
- 任何字体、纹理、图标的商用/分发许可必须在设计冻结前记录。

## 6. 验收标准

- 五个一级入口和地点详情共用同一套层级、色彩与组件语言。
- 一至三层小碗在 16 至 24 px 尺寸下能可靠区分，选中、禁用、聚合状态均有定义。
- 时间线有明确的“真实记录”质感，但文字可复制、可缩放、可被读屏工具理解。
- 轮播无自动抢焦点；首屏性能、图片加载失败和弱网回退符合设定阈值。
- 可访问性、视觉回归、性能预算、移动端真机和用户可用性测试通过。
