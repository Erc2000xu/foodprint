## 1. 本轮已确定的基础

### 1.1 两字体体系

| 角色 | 字体 | 可用范围 | 不可用范围 |
| --- | --- | --- | --- |
| 功能字体（`F`） | **思源黑体 SC** | 导航、标题、正文、表单、地点名、地址、按钮、状态、用户内容、管理页 | 无；它是全站默认字体 |
| 创意字体（`C`） | **站酷小薇体** | 每页至多一条短的品牌/情绪标题；固定空状态或成功状态中的一句短话 | 按钮、输入、地址、日期、错误、隐私、动态地点名、用户笔记、长文、管理页 |

- `C` 只在本表标记为“创意”的句子中使用；其余全部使用 `F`。
- 创意文案不承担解释规则的职责。规则、后果和权限说明必须使用直接的功能语言。
- 落地时本地托管两款 OFL 字体，并随代码保留字体版本与 LICENSE/OFL 文件。详见 [字体对比图](../design/v1-4-typography/font-comparison-v1.png)。

### 1.2 品牌化清洁规则

- App 的用户界面不展示任何第三方地图/地点服务品牌名。统一使用“地点搜索”“地点建议”“地点信息”“地图应用”“系统整理”等食迹自己的说法。
- “当前文字”列只用于核对代码原文，不代表上线文本；其中出现的第三方服务名称必须在实现时替换，不能复制到候选文案、截图或设计稿。
- 文案要像一个认真记录食物的人在说话：具体、克制、有人情味。避免“为你带来”“开启探索”“智能推荐”“内容沉淀”等产品模板词，也避免过度撒娇、网络口头禅和古典化表达。
- 判断标准：读起来像食迹，而不是像客服话术、宣传稿或 AI 自动生成的产品说明。

### 1.3 审核标记

| 标记 | 含义 |
| --- | --- |
| 保留 | 当前文字准确，可直接沿用 |
| 候选 | 历史列名；本轮已由项目负责人确认，开发以该列文字为准 |
| 待重写 | 当前文字或行为说明有歧义，必须确认后才可开发 |
| 不改文案 | 动态数据、第三方返回或无可替换的固定文案；只规定字体/格式 |

## 13. 需在逐页会中决定的产品问题

1. **发现的朋友口吻：** “朋友真实推荐”改为“朋友吃过的好地方”后，是否弱化了“真实推荐”的产品承诺？
2. **去试试主标题：** 是否采用 `听说不错，找天去试试。`；若采用，说明文字是否使用“想去”而非“想试”？
3. **记一顿主标题：** 是否采用 `这一顿，值得好好记下。`，替代带有判断感的现有句子？
4. **饭后聊：** 是否采用 `吃过以后，大家想说的话。` 作为唯一的创意标题？
5. **我的页：** 是否将页面标题缩为“我的”，把成员与管理相关能力放在“共同地图管理”分组下？这需要轻微的信息层级调整，不只是改字。
6. **角色中文化：** 是否将 Owner / Admin / Member 改为“创建者 / 管理员 / 成员”？若不改，所有解释性文字保持英文角色名一致。
7. **删除确认：** “删除这次记录”“删除照片”是否增加二次确认弹窗？若增加，需新增确认标题、后果说明、确认/取消文案。
