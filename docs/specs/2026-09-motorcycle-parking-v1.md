# 食迹 Foodprint｜摩托车停车地图 V1

> PRD＋开发说明 · 2026-09-07
> 状态：仓库实现完成，待 CI／临时库重放、真实账号初始化、真机验收与发布审批；本文件中的页面、接口和资产路径均为开发要求。
> 基础：现有食迹网页／PWA、V2.4.2 代码、高德 JS API 2.0、现有账号体系。功能称为「停车地图 V1」，食迹整体版本号与发布日期另行安排。
> 视觉依据：[用户提供的首页截图](../design/motorcycle-parking-v1/home-reference.png)。

## 1. 目标与本次范围

在现有食迹中增加一个仅向授权成员开放的摩托车停车地图，记录自己实际停过、认为方便停车的位置、路段或区域。复用现有地图、登录、配色与控件，减少操作和开发量。

本次交付：**首页纯图标入口、停车地图、点／路段／区域标记、方便停车勾选、备注、查看／编辑／删除、停车功能授权管理。** 授权管理本次实现，首次上线授权名单为空，只有项目负责人的指定账号可用；以后可直接添加使用者，无需再开发授权入口。

停车记录独立于餐厅记录，不进入美食地图、餐厅数量、推荐等级或饭后聊。本版不做照片、收费分类、评分、评论互动、导航规划、自动吸附道路、自动获取园区边界和行驶轨迹。

**用户已确认：共享停车地图，各自编辑自己的记录。** 所有已授权用户查看同一张停车地图，包括其他授权成员贡献的记录；编辑和删除仅限本人创建的记录。指定停车管理人负责授权，也遵循「只编辑、删除自己记录」的内容规则。

## 2. 页面与入口

| 位置 | 要求 |
| --- | --- |
| 首页「发现」 | 在截图右上方深绿色「搜索」按钮正下方，新增一个摩托车图标按钮；与搜索按钮水平中心对齐，位于筛选行右侧、当前范围卡片上方。以控件布局定位，不写死截图像素。 |
| 按钮样式 | 只有图标，无可见文字、角标或悬浮文案。使用完整的浅蜜黄色圆角方形按钮图，带轻微倒角、柔和边缘和居中的摩托车；沿用首页暖色调与软陶质感。完整按钮建议 44×44 CSS px，上方间距 8–12px。提供不显示在画面上的无障碍名称「打开停车地图」。 |
| 小屏适配 | 筛选行给按钮预留独立列；筛选项可横向滚动，不能盖住按钮。搜索建议和筛选浮层打开时位于按钮上层。 |

| 停车地图 `/parking` | 顶部返回「发现」与页面标题「停车地图」，地图可拖动、缩放；沿用现有定位按钮，底部提供「新增标记」。点击已有点、线或区域，打开底部详情卡片。 |
| 「我的」 `/admin` | 仅指定停车管理人看到「停车地图权限」区域，显示已授权人数、「添加用户」及名单中的「撤销权限」。这里用于管理授权，使用入口仍在首页。 |

返回发现页时恢复原有美食筛选与视野。停车页沿用现有应用外壳、底部导航、安全区、备案展示及底部面板样式，不新增一级导航。

### 图标资产要求

历史设计记录曾建议先用 **ImageGen** 生成正式摩托车图标；本次实施授权以现成 V3 资产为准，直接接入，不重新生成。图形采用清晰的摩托车侧面轮廓、轻软陶质感；用户已从两款候选中选择 **A 美式巡航**，并要求颜色稍浅、镀铬效果更明显。沿用 A 的低座、长车身和 V 型发动机，车漆提亮为略带深青色调的深石墨灰，发动机、双排气管及轮圈使用更明显的亮银镀铬质感；配以暖米白和少量橙色。无文字、字母或品牌标识，小尺寸下能与自行车、定位图标区分。方向、修订与提示词见[摩托车图标设计记录](../design/motorcycle-parking-v1/README.md)。

用户最新要求覆盖最初的「单独透明摩托车＋外层按钮」方案：交付包含浅蜜黄色底板的完整圆角方形图标，无棋盘格，摩托车细节按小图标适当简化，保留灰色巡航车与亮银镀铬效果。设计源、生成提示词和修订存于 `docs/design/motorcycle-parking-v1/`，完整按钮资产建议放在 `public/icons/map-controls/motorcycle-parking-button-*.png`。接入以整枚按钮 44×44 CSS px 为基准准备 1×／2×／3× 资源；容器只负责点击、焦点和状态反馈，不再叠一层暖白按钮底。验收检查首页实际尺寸下的轮廓、圆角、边缘和色彩协调，设计文件完成不等于停车功能已接入。

## 3. 标记操作与填写字段

统一流程：**新增标记 → 选「点／路段／区域」→ 拖图选位置 → 完成选点 → 填信息并勾选 → 保存。**

手机优先使用固定中心准星：拖动地图把位置对准准星，再点「确认位置／添加节点」。浏览地图时不进入绘制；选点时仍可拖动和缩放，避免手指画线与拖图冲突。

| 类型 | 操作及完成条件 | 地图表现 |
| --- | --- | --- |
| 点 | 对准一个位置，点「确认位置」。 | 一个停车点图标。 |
| 路段 | 对准起点「添加节点」，再选终点；弯道可补中间节点，至少 2 个不同节点才可完成。 | 深青绿色折线；实时显示「约 XX 米」，可以记录约 50／100 米路边，不限制为固定长度。 |
| 区域 | 沿园区或停车区域边缘添加节点，至少 3 个不同且不共线的点；完成时自动闭合。 | 深青绿边框与低透明度填充。 |

选点阶段有「撤销上一个点」「重新选」「完成」「取消」。点支持重新定位；路段和区域修改几何时复用整段重选流程，本版无需逐顶点拖拽编辑器。形状存为地理坐标，拖图和缩放后仍贴合原位置。

| 字段 | 必填 | 输入及规则 |
| --- | --- | --- |
| 标记方式与位置 | 是 | 上一步生成，显示类型和地图预览；不要求填写经纬度、详细地址或选择高德商户。 |
| 名称 | 否 | 单行，最多 30 字，例如「园区东门外」。留空自动显示「停车点」「路边停车」或「停车区域」。 |
| 方便停车 | 是 | 复选框「我确认这里方便停摩托车」，默认不勾选，必须主动勾选才能保存。表达用户的实际经验。 |
| 备注 | 否 | 多行文本框，最多 500 字，保留换行；提示「例如：入口在东侧，靠墙停，晚上比较空」。只做备注，不做评论或回复系统。 |

示例：路段 → 沿东侧路边选两个点，预览约 80 米 → 名称「园区东门外」→ 勾选方便停车 → 备注「入口右手边靠墙，停过两次」→ 保存。

保存成功后关闭表单、选中新标记并显示详情。详情展示名称、类型、「方便停车」、备注、创建者显示名及更新时间；仅本人记录提供「编辑」「删除」，其他人的记录只读。已有方便停车勾选保持原值。若后来不方便停车，作者可删除记录，删除前一次确认。保存失败保留本次内存草稿并允许重试；提交中防重复点击，成功提示以服务端保存结果为准。离开未保存内容时提示是否放弃。

其他授权用户下次打开／回到停车页或手动刷新时看到新增与修改；首次加入授权即可看到已有共享记录。本版不新增实时协同推送。

## 4. 账号与授权规则

| 身份 | 首页入口／停车功能 | 记录权限（共享查看、各自编辑） | 管理授权 |
| --- | --- | --- | --- |
| 项目负责人指定账号 | 默认有 | 查看全部共享记录；创建、编辑和删除自己的记录 | 可添加、撤销其他用户 |
| 显式授权的现有用户 | 有 | 查看全部共享记录；创建、编辑和删除自己的记录 | 无 |
| 未授权用户，包括其他 Owner／Admin | 无 | 无 | 无 |
| 未登录、被暂停／移除、已撤销授权 | 无 | 无 | 无 |

- 指定管理人绑定**稳定的现有账号 ID**，不按昵称、邮箱文案或「任意 Owner／Admin」判断；初始化时核对该账号确为当前项目负责人的 Owner 账号。管理人本人不出现在可撤销名单中。
- 「添加用户」复用现有小组有效成员目录，可按现有昵称／账号标识搜索选择；不创建第二套账号，不改变用户原来的 Owner／Admin／Member 身份。
- 授权与撤销均真实落库；重复授权保持幂等。撤销只关闭停车功能，原食迹账户继续可用。暂停、移出小组会使停车权限失效；恢复成员身份不会自动恢复旧授权，需重新授权。
- 撤销后，该用户失去全部停车数据访问权；其既有记录继续保留在共享地图中，重新授权后恢复本人编辑权。撤销权限不等于删除贡献；管理人也不能借授权管理修改他人的记录。其他普通用户看不到授权名单、停车记录或相关统计。
- 首页显隐、页面访问、服务端操作和数据库 RLS 使用同一权限口径。直接输入地址、伪造用户 ID、请求底层接口均不能绕过；已登录但无权访问页面时返回通用 404，接口拒绝且不返回数据。
- 撤销生效后的请求立即拒绝。停车页回到前台、路由切换和提交前重新校验权限；打开期间每 60 秒复核一次，失效后清空页面记录与草稿并退出。私有内容不进离线缓存或公共日志。

## 5. 基于现有程序的开发方案

### 5.1 复用与新增位置

| 代码位置 | 开发内容 |
| --- | --- |
| `src/app/page.tsx`、`src/components/map/map-browser.tsx` | 新增独立的 `canUseParking` 权限结果与入口，不能复用当前表示 Owner／Admin 的 `canManage`。 |
| 新增 `src/app/parking/page.tsx`、`actions.ts` 与 `src/components/parking/` | 停车页面、地图选点、表单与详情；页面先鉴权，再下发停车数据和地图配置。 |
| `src/app/admin/page.tsx` 与新增授权管理组件 | 独立 `canManageParkingAccess` 判断；接入既有成员目录，按需加载管理名单。 |
| `src/lib/amap/load-amap.ts`、`src/components/map/map-adapter.tsx` | 复用 SDK 加载、同源安全代理、定位和视野处理；新增停车覆盖物适配层，封装点／线／面的展示与选点。 |
| 新增 `src/lib/adapters/parking-repository.ts`、`src/lib/parking/` | 集中封装停车读写、权限、数据校验与几何处理，业务组件不散落直连高德／数据库。 |
| `supabase/migrations/`、`src/app/globals.css` | 新增数据表、RLS、授权操作及审计；样式沿用现有变量与控件。 |

地图使用现有 `amap://styles/whitesmoke`，通过 `AMap.Marker`、`AMap.Polyline`、`AMap.Polygon` 绘制；长度由选点坐标计算。沿用 GCJ-02，内部坐标数组固定为 `[经度, 纬度]`。位置为用户手动记录，不依赖高德 POI ID、逆地理编码或付费边界服务。

**空数据也必须能打开停车地图并新增第一条记录。** 现有首页会在美食地点为空时关闭该页动态地图，停车页不能沿用“必须有餐厅／已有标记”的初始化条件；入口权限也不依赖美食地点数量。仅已授权用户进入停车页时加载绘制代码，不把新模块加入所有用户的首页首屏。

进入时优先采用本会话停车视野，其次采用本会话发现页视野，最后用现有默认城市中心；主动点击定位时沿用已有一次性定位和同意流程。自动定位结果不保存为停车记录或行驶轨迹。

### 5.2 最小数据模型（建议命名）

| 表 | 主要字段与作用 |
| --- | --- |
| `parking_feature_config` | 单一配置：`id`、`group_id`、`manager_user_id`、`enabled`。由受控初始化写入指定账号，数据库可验证；未配置时默认关闭。 |
| `parking_feature_access` | `group_id`、`user_id`、`granted_by`、`granted_at`、`revoked_at`，小组＋用户唯一；授权只管理本功能，关联现有账号。 |
| `parking_marks` | `id`、`group_id`、`created_by`、`geometry_type(point/line/area)`、`coordinates(jsonb)`、`coordinate_system(GCJ-02)`、`name`、`is_convenient`、`comment`、`created_at`、`updated_at`、`deleted_at`。 |

复用现有 PostgreSQL，第一版无需引入 PostGIS。点存 1 个坐标，线存节点数组，区域按统一约定存首尾闭合的单一外环；不支持多片区域或内孔。长度作为派生展示值，不让用户手填。

服务端与数据库写入边界都校验坐标、节点数量、文本上限及 `is_convenient=true`；拒绝越界／非有限坐标、重复相邻节点、零长度线、零面积或自交区域，线／区域最多 100 个有效节点。用户、小组、创建时间由服务端身份确定，客户端不能修改记录归属。

RLS 读取检查功能开启、小组及成员均有效、指定管理人／显式授权和配置中的同一小组，允许读取该停车地图的全部有效共享记录；不要求记录作者仍有使用权限。创建必须归属当前用户，更新和删除额外要求 `created_by = auth.uid()`，包括管理人也不能改他人记录。授权写操作只允许指定管理人，普通客户端不可改配置或自行添加授权；安全函数固定查找路径并限制执行权限。成员暂停／移除时，同一事务撤销其停车授权，恢复成员身份不清除撤销记录。业务读写使用用户会话，不能用高权限密钥绕过 RLS。删除使用 `deleted_at`，默认查询排除已删除记录。

### 5.3 接口、异常与数据边界

- 提供 `getParkingAccess`、`listParkingMarks`、`createParkingMark`、`updateParkingMark`、`deleteParkingMark`，以及管理专用的 `listParkingMembers`、`grantParkingAccess`、`revokeParkingAccess`；可用现有 Server Actions／RPC 实现，无需另起后端服务。
- 权限只由当前登录身份计算；接口拒绝跨作者写入及跨小组读写，允许已授权用户读取当前停车地图其他作者的记录。列表按稳定游标分批读完授权数据，不能把默认行数截断伪装成完整地图；创建者只返回显示名，不附带邮箱或完整成员目录。写入应支持同一次提交幂等重试。
- 新增授权、撤销、标记创建／修改／删除写入既有审计体系；不记录备注正文、坐标或定位起点。停车记录不混入既有共同美食导出；本版不新增停车导出界面，部署记录说明备份范围。
- 地图加载失败时保留已授权共享记录的简短列表，可查看文字，作者可编辑名称／备注、删除，并可重试地图；无法操作地图时禁止新增或修改位置。数据读取失败单独报错和重试，不显示为「没有记录」。
- 高德接入沿用现有安全代理、总开关、免费范围与配额约束；不增加自动付费。停车功能另有独立开关，关闭时首页入口、页面和读写同时关闭；仅地图服务关闭时仍可使用上述列表降级。

## 6. 开发顺序与发布

1. **权限与数据：** 新增 migration、配置初始化、RLS、授权管理和数据校验；默认不授权其他账号。
2. **图标与入口：** 按最新授权直接接入现成 V3 资产，完成实际尺寸检查、首页按钮和授权显隐。
3. **停车地图与表单：** 复用地图风格，实现三种选点、勾选、备注与增删改查，再接入「我的」授权区域。
4. **验证与发布：** 完成应用检查、干净数据库 migration 重放、角色权限与真机验收后，按现有 [Release SOP](../RELEASE_SOP.md)发布；先数据库后应用。实施前按 [开发工作流](../DEVELOPMENT_WORKFLOW.md)登记版本、Spec 与权限／数据决策。本次仓库实现已完成，外部环境验证与发布审批仍按实现记录执行。

初始化使用受控发布步骤，将核对后的现有账号 ID 和小组 ID 写入配置，记录结果；不是让首次访问者自动成为管理人。故障时先关闭停车功能；可回退应用，保留新增表和用户记录，通过后续 migration 修复，不删除历史数据。

评估：地图展示与基础记录难度较低，手机选点、权限隔离和现有成员生命周期联动为主要工作量；整体为中小型功能迭代，非全新应用。
