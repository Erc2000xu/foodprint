## 1. 背景与问题

V1.4 Preview 体验中发现两类视觉问题：

1. 发现页 `/` 的地点卡片右上角“详情 / 管理”入口，当前使用文字 `···` 作为图形。截图中三个点的可视尺寸明显偏大，且不同字体、浏览器和行高会影响点的间距与垂直位置。这个入口仍需保留查看地点详情、管理到访记录和下架地点的原有权限与流程。
2. 发现页与“我的” `/admin` 中，多个按钮和链接的文字没有稳定地在按钮背景内水平、垂直居中。重点包括：地点卡片的“下回吃”、管理列表的“查看 / 管理记录”、安装区的“安装到设备”，以及复用 `.text-button`、`.secondary-button`、`.primary-button` 的其他操作。

这次迭代先确定一个小而稳定的详情按钮视觉资产，再进行代码级嵌入和全局控件对齐修复。

## 2. 目标与成功判断

- 详情按钮在地点卡片右上角保持小巧、清晰、可识别，不再受文字字体或基线影响。
- 详情按钮在浅色照片、无照片卡片和窄屏下均有足够对比度，不遮挡地点标题和卡片信息。
- 详情按钮仍是原生 `<button>`，保留 `aria-label`、`aria-expanded`、键盘操作、点击外部关闭和原有管理权限；图片只负责视觉外观。
- `/` 与 `/admin` 中纳入本次范围的按钮文字在自己的边框内水平、垂直居中，图标与文字之间的间距稳定。
- 在 320、375、390 px 宽度下不出现按钮溢出、文字裁切、意外换行或卡片横向撑破。
- 不改变地点下架、恢复、到访管理、邀请、导出、安装和下回吃的业务逻辑、权限、数据结构或接口。

## 3. 范围

### 3.2 控件对齐修复

统一检查并按需修复以下控件：

- 发现页：地点卡片详情按钮、`下回吃`、搜索/筛选/地图切换相关操作。
- 我的页：`查看 / 管理记录`、`安装到设备`、`下载我的 JSON`、`导出共同地图`、邀请操作、成员状态/角色操作。
- 与这些控件共用基础类的其他页面按钮，只在不改变文案和交互的前提下修正对齐。

统一 CSS/DOM 规则：

```css
.ui-action,
.text-button,
.secondary-button,
.primary-button {
  box-sizing: border-box;
  display: inline-flex;
  align-items: center;
  justify-content: center;
  vertical-align: middle;
  line-height: 1.2;
  text-align: center;
}
```

具体实现需结合现有类名，不强制新增一套视觉系统。所有按钮和按钮样式链接必须满足：

- 高度由 `min-height` 与明确的 `padding` 共同决定，不能依赖浏览器默认行高。
- 单行文字左右居中；多行说明不得挤进按钮，必要时通过容器布局处理，而不是负 margin。
- 图标采用 `display: block` 或 `inline-flex`，与文字使用明确的 `gap`；不使用脆弱的 `vertical-align`、负 margin 或字符空格校准。
- `:focus-visible` 保留清晰的焦点环；`disabled` 状态不改变布局尺寸。
- 管理列表行在宽屏中垂直居中；窄屏允许操作区换到下一行，但文字与边框仍保持居中。

## 4. 非范围

- 不改变 Owner/Admin/Member 权限判断和 Server Action。
- 不新增或修改 Supabase migration、表、RLS、Edge Function 或环境变量。
- 不重做整套图标系统，不把本次按钮候选扩展到饭后聊、记一顿的内容图标。
- 不在本次迭代中调整整体字号、字体选择或 V1.4 已批准文案；若发现新的内容问题，另立任务。

## 5. 现状技术定位

- 详情入口位于 `src/components/place/place-management-control.tsx`，当前按钮以 `···` 文本渲染，样式位于 `src/app/globals.css` 的 `.management-menu-button`。
- 发现页地点卡片位于 `src/components/discover/discovery-place-card.tsx`，管理入口通过 `canManage` 条件挂载。
- 我的页地点管理列表位于 `src/components/admin/place-content-management.tsx`；安装提示位于 `src/components/pwa/install-guide.tsx`。
- 主要对齐基础类位于 `src/app/globals.css`，包括 `.text-button`、`.secondary-button`、`.primary-button`、`.inline-action` 和 `.management-list`。
- 修复时先确认问题来自元素默认基线、`line-height`、`display`、padding 或 flex 对齐，再改最小范围；不通过放大或缩小字体来“追”视觉中心。

## 7. 验收标准

### 7.1 发现页

- Owner/Admin 在 `/` 的每张可管理地点卡片右上角看到统一尺寸的详情图形；图形不再显示为放大的三个文字点。
- 点击后仍能打开“查看地点详情”“管理到访记录”“下架地点”；点击卡片正文不会被详情按钮的图片层拦截。
- 键盘 Tab 可以到达按钮，Enter/Space 可以打开菜单；屏幕阅读器读到 `管理{地点名}`。
- 点击卡片外部会关闭菜单；下架确认弹窗、权限控制和成功/错误反馈与 V1.4 一致。
- 普通 Member 不出现管理按钮，也不能通过图片路径获得管理能力。

### 7.2 我的页与公共按钮

- `/admin` 的“查看 / 管理记录”、 “安装到设备”、导出、邀请、成员状态和角色操作，文字与边框上下左右视觉居中。
- `/` 的“下回吃”、搜索、视图切换及其他纳入范围的按钮，在有无图标、进行中和 disabled 状态下都不跳位。
- 320 px 下管理列表操作可换行但不横向溢出；375/390 px 下主要操作保持一行且不遮挡内容。
- 不出现因改动全局按钮类导致的输入框、链接、弹窗按钮尺寸回归。

### 7.3 视觉与资源

- 选定图片在浅色和照片背景上有足够对比度；透明边缘无绿幕/白边残留。
- 图片以本地资源加载，Network 不出现新的运行时外部图片请求。
- 图片缩放到 28 px 左右仍可识别，不能出现模糊、锯齿、裁切或纹理脏点。
